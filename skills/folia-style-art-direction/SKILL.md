# Folia 风格导演

交付能随任意歌词成立的风格，而非一段漂亮但固定的演示。用户的画面意图优先；先找出这幅画独有的关系，再决定字如何出现、停留和离开。

## 开始时加载

- 首先读[个性与样式](references/taxonomy.md)，或 `folia_style_catalog` / `folia_style_read_guide({topic: "taxonomy"})`。个性是完整视觉设计，样式是可复用的歌词呈现模板；分类不能与逐字/逐句/组句三种释放语法混为一谈。MCP brief 自动附带本规范。

- 用 `folia_style_brief` 获取本 skill、相关参考与当前项目路径；已通过 brief 读到本段则不重复调用。没有 MCP 时直接读这些文件，工作仍可继续。
- 设计或修改效果时读 [内置设计依据](references/builtins.md)。需要核实实现时调用 `folia_style_reference`，按风格读取实际源码；不要把目录名称当作效果证据。
- 输入是壁纸、视频或人物场景时读 [重建经验](references/reconstruction.md)。
- 决定歌词出现方式和发射者运动时必须读 [三种歌词释放语法](references/lyric-release.md)，或调用 `folia_style_read_guide({topic: "lyric-release"})`。依据素材的艺术风格选择逐字生成、逐句生成或字词浮现组句；不是按行号轮播三种特效。
- 开始写代码之前读 [动态编排与验收](references/motion-and-acceptance.md)。API 以 MCP 的 `folia-style://renderer-api` 或交付目录的 `renderer-api.d.ts` 为准，不照搬内置专用字段。不支持 resources/prompts 的客户端直接调用 `folia_style_read_guide({topic: "renderer-api"})`；本 skill 的制作流程适用于 Codex、Claude、DeepSeek Harness、WorkBuddy 等支持 MCP tools 的宿主，不依赖某家的 skill 自动发现。

## 工作顺序

1. **观察并确定主次。** 记录来源、关键时间点、主体/负空间、颜色与材质、动作的发起者。分开写“看到的”“推测的”“缺少证据的”。用一句话描述作品，例如“少女呼出的歌声进入夜风，渐渐变成远处的微光”。列出不应抢走注意力的元素。
2. **提炼两条相关的内置原则。** 写明来源文件/符号、为何适合、如何转译。例如借凝彩的跨句方向延续与绘光的弱光层次；安静夜景不因此套上花火的强爆发。不能只写“高级、灵动、电影感”。
3. **先编排乐句，再设计单字。** 产出简短 motion plan：可用信号 → 乐句状态 → 空间/时间行为 → 状态间交接 → 阅读保障。稀疏句、密集句、长音、换气和高潮应有有因果的差异。固定一条曲线加噪声、按行号轮播曲线都不足以解决机械感。允许有动机的主题复现；不为了凑数量增加无关轨迹。
   在 plan 中分别写明 `素材证据 → 主释放形式 → 两个未选方式及原因`、`出生位置 → 生成后是否固定 → 局部运动范围`、`退场触发事件`。逐字是依次留下，逐句是整句共享入场，组句是各字词独立浮现并短距离聚拢；不能只是同一动效换速度。猫与蜜蜂采用出生处固定；夜莺v1.3采用女孩附近可见出生→真实输送→固定留声点微浮。两者均在第N+2句开始出现才让第N句渐隐。不要混淆发射点和驻留点。不要把“字从蜜蜂生成”理解成“字跟着蜜蜂走”，不要按当前弧长重算旧字、裁掉应保留的旧尾部或把字送到固定字幕槽。逐字时间驱动发射者速度，纯音乐时发射者慢游，保留文字遵从自己的生命周期。
4. **建立空间约束。** 横竖屏分别决定文字走廊、人物面部/手部禁入区、翻译区、边缘余量。人物发声点须跟随同一套角色/镜头变换；手动给静态嘴部坐标不等于绑定。长词按完整文字包围盒验收，不能只保证中心点不出界。
5. **实现可回放的动作。** `update(scene)` 编译分句、时间和带种子的决策；画幅/字体只在 `frame` 中，`render(frame)` 在布局缓存键变化时重测排版，其余帧从宿主绝对时间求状态。键涵盖相关文字、width/height/dpr、字体/字重/缩放及字幕参数，scene 更新也使缓存失效；不能等待 resize 或换字体触发 `update`。稳定 seed 带来可复现的变化，不等于固定整首歌。区分字的唱段结束、可读停留结束、粒子消散结束。音符是歌词转化的一部分，避免给每个字永久贴同一个 ♪。
6. **先看连续片段，再看截图。** 用真实短句/长词/快速句/长音/间奏连续播放，先审美复查，再跑 Studio 技术验收。若报告“单调”，定位重复发生在发射点、空间形状、节奏、速度、字形关系还是镜头层级；改对应结构，不盲目提高随机幅度。可把实际轨迹传给 `folia_style_review_motion` 辅助诊断。
7. **交付证据。** 按验收参考交付包、源码、设计依据、连续预览、横竖屏、技术报告与未解决差距。调用 `folia_style_check_pack` 只证明包格式，不证明代码执行或审美。MCP 诊断也不授予审美通过；没有观看记录就写未完成，不自行填“合格”。

## 人物轻哼的额外审美检查

夜莺v1.1水平字幕、v1.2弯曲字幕均被用户否定。v1.2虽有微光连接女孩，真实字形却直接在远处终点渐显，不能称为“从女孩流出来”。v1.3必须以**真实字形**完成女孩附近可见出生→连续路径输送→减速落定→原处微浮→N+2渐隐。每个字出生时采样角色发声点，路径与驻留点随后冻结；新字继续流出时，已落定的字不能跟着流动。出生时已有可辨字形，不可先透明飞到远处再显现；装饰粒子不能充当文字运动证据。保留曲线句形，但验收应跟踪同一个字的出生、途中、落定三帧以及落定前后速度连续性，不能只看整体字幕是否弯曲。飞行区域与驻留文字区域分开检查，旧句不为过路新字挪位。

## 关键边界

- API 2 的输入包含歌词时间、chorus、瞬时 audio/spectrum 等，但没有现成的旋律音高、准确 BPM 或内置完整 songPart。用推断时明确标注，不能伪称做了准确口型/音高跟随。
- 对本地参考素材只读分析；第三方图像、图集、视频不随 skill 分发。资产许可和重建偏差另行记录。
- 宿主隔离 Worker 无 DOM/网络；依赖需本地打包。字体、缩放、减少动态效果、暂停/跳转、无歌词状态都属于设计，不是最后补的开关。
