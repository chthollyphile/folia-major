# 个性与样式

用户定义的两类用途是本项目的制作契约。不要按元素数量或实现框架重新分类，也不要把分类标签当作质量认证。

## 个性 — personality

商籁（sonnet）、凝彩（tempera）、绘光（lumiere）、花火（hanabi）、町景（machi）、雾笺（nebbia）。它们是主体、场景、材质、色彩、镜头和歌词关系已经组织在一起的完整视觉设计。夜莺与猫蜂整合包也是以完整个性为交付目标。

制作个性应先分析素材，再决定歌词从哪里生发、是否经过输送、在哪里停留及何时退场。可以借用一个或多个样式的歌词组织原则，但不能只给普通字幕套一张壁纸就声称完成个性设计。个性内部某段歌词代码可以作为研究依据；这不把整套成熟设计变成可直接套用的歌词模板。

## 样式 — lyric-template

流光（classic）、心象（cadenza）、云阶（partita）、浮名（fume）、倾诉（tilt）、回环（claddagh）、莫奈（monet）、时计（pendolo）、群唱（cappella）、镜台（diorama）、静止（still）。它们在制作流程中的职责是**歌词呈现模板**：字词如何出现、排布、强调、组句、停留和退场。

提炼样式时只继承对歌词有用的行为。某些内置实现同时画封面、头像或几何场景，并不意味着整段 React/Three.js 源码应直接搬进风格包，也不改变用户给出的分类。把附属背景、相机或装饰与歌词行为分开，在个性里重新按素材编排。

“随机”是播放选择，不是第十二个模板。风格包入口是容器，不是第十八个内置设计。模组未知类别不得擅自标成成熟个性。

## 选用与移植

1. 调用 `folia_style_catalog` 获取当前明确分组及源码文件，再用 `folia_style_reference` 分页阅读对应实现。
2. 在方案中写明目标 `kind`，以及“参考样式 → 保留的歌词行为 → 去掉的附属元素 → 对当前素材的改造”。可用 `lyricTemplate` 记录一个主要内置样式 ID。
3. **类别与释放语法是两条轴。** `personality` / `lyric-template` 是交付范围；逐字 / 逐句 / 字词组句是歌词入场方式。个性和样式都可以使用其中一种或按素材有依据地组合，不能用类别代替入场决策。
4. 内置源码依赖播放器的 React、共享时钟、Three.js 或专用辅助模块；它是移植依据，不能作为 Worker 的运行时模块名。转换到 renderer API 2 的 `update(scene)` / `render(frame)`，本地打包所有必要依赖。`lyricTemplate` 是参考来源，不会自动加载内置程序或自动与场景混合。
5. 命令 `new <目录> <id> lyric-template` 和 Studio 的“载入歌词模板”提供独立的纯歌词起点；它是学习骨架，不是上述十一种内置效果的等价复刻。完整个性起点使用 `personality`。
6. 起点对阿拉伯语等连写、复杂塑形或混合方向文本降级为完整句子绘制，保持字形和阅读顺序；不能把拆散字母误称逐字效果。需要这些语言的逐字/组句效果时，应另外实现保留塑形的遮罩或文字排版。入场须在行结束前完成，N+2 以对应模式的实际首个非空字出现时刻计算，不能被早于首字的行时间戳触发。

## 分类与鲁棒性验收

- 新包显式填写 `kind: "personality" | "lyric-template"`。旧 API 1/2 包缺省时只按个性兼容显示，不改文件内容、ID、存储键或版本；这不是对旧包质量的认证。未知类别、把个性/随机填进 `lyricTemplate` 必须拒绝，并保留当前可用包。
- 样式验收聚焦歌词行为与复用边界；个性还要检查主体关系、空间、镜头、材质与情绪。格式通过不能证明类别声明真实，仍需看连续输出。
- 保留用户明确要求的出生、输送、停驻与 N+2 退场规则。尤其夜莺的字必须真正在女孩附近出现再输送，猫蜂旧字不得跟随移动的发射者。
- 检查空歌词、长词、快速歌词、横竖屏、字体缩放、减少动态和任意跳转。更换模板不能擅自改变生命周期。
- 连续导入、编辑后返回的旧导入、切包后返回的截图/验收结果，都不得覆盖最新草稿或冒充新包证据。存储失败保留原有库并明确报错。
- 分类在播放器选择器、包管理、Studio、MCP、CLI 和导出文件中保持一致；更新安装包后重启旧 MCP 会话再验证发现的新工具。
