# 壁纸与视频重建：夜莺案例

本案例来自用户本地 Wallpaper Engine 项目 `3448877775`：原画 Rella，壁纸作者夜莺 Night。只保留方法和失败经验，不分发其原始艺术素材。这是旧原型的历史案例，源码不属于本 MCP 提案；下文是该次分析观察，不是所有 Wallpaper Engine 文件的通用格式承诺。

## 先辨认资源，再决定怎么重建

1. **库存**：先读 project 元数据、预览、文件头和大小。该项目为 PKGV0022 容器、3840×2160 场景；不是把 `scene.pkg` 当成视频播放。包内有场景 JSON、材质、纹理、模型及嵌入视频。保持源目录不变，另建工作目录。
2. **还原空间**：记录图层 origin、scale、遮挡顺序、锚点及原坐标系（该场景 Y 向上）。将场景坐标、贴图局部坐标、屏幕坐标和相机变换区分开；逐层对照预览后再加动画。
3. **图集不是插画**：女孩纹理是拆开的身体部件；直接把整张 atlas 当背景会得到碎片。该次按 MDLV0023 网格的顶点/UV/三角索引拼回，再加自己的摆动。不同文件版本必须重新验证结构，不能推广固定 stride 偏移。
4. **只转换所需资产**：先挑天空、城市、栏杆、人物、窗帘、椅子、包等图层。大动画纹理全量解码会耗时/内存失控。左帘纹理包含带色键的 MP4；该次只提取图像并重做摆动，因此不能声称复原了原始视频动画。
5. **分开还原和创作**：原画/层次还原可对照原预览；新写的呼吸、头发、歌词和运镜属于原创程序解释。该版本取固定夜景，没有完整复刻原作昼夜、时钟和所有特效，报告要列清。

工具来源需可追溯：该次采用 [RePKG](https://github.com/notscuffed/repkg) 纹理转换，并参考 [pkg_parser 的模型格式实现](https://github.com/wqLouis/pkg_parser)。工具版本、实际转换命令、使用素材和署名记录到包内说明，不把临时绝对路径写死在可分发代码中。

## “技术通过但画面单调”的失败

首版把歌词从一个静态发射点沿同一弧线流出；每个字只有少量 seeded 偏转。它实现了逐字显现、消散、回放和横竖屏，也通过了运行测试，但用户仍指出“哼唱轨迹太固定”。测试覆盖了能否运行，没有检验多乐句的观感。

修正思考顺序：

- 先分辨问题是“路径曲率一样”，还是每句的节奏、组团、近远与释放方式都一样。仅添加 sin 抖动或每句换颜色仍是同一模板。
- 将一次呼气视为有起、承、停、散的乐句事件。词/字在事件中有相对位置，不能所有字都作为独立相同粒子飞行。
- 用可用的间隔/密度/长音/chorus 信号选择有意义的行为。例：近身轻语、细长上扬、宽幅远流、句尾小回旋；这些只是方向候选，不是强制四条轨迹轮播。
- 复用主题时说明为何返回，保留共同的风向/光色，同时改变组团、速度包络或停留位置。不能只靠换 family 名称伪装新形态。
- 发声点随头部同一变换走；衣物/发梢有延迟而不是所有部件同相正弦。轻快哼唱可有节奏感，但无音素/音高输入时不要声称真实口型同步。
- 修复后至少看一段跨稀疏句、密集句、长音和换气的连续预览，再看两种画幅；三张美观截图不能证明变化成立。

## 这次确实踩过的工程边界

| 症状 | 原因与可复用检查 |
| --- | --- |
| 长词尚未唱完就淡出 | 生命周期只按发射时刻算；停留至少覆盖最后一个 glyph.end，再进入释放。最后一个字还未唱完时不能已经不可读 |
| 长词未淡出但出了屏幕 | 活着不等于可读；按完整词宽、字体、边缘和人物禁入区决定停留位置，横竖屏分别测 |
| Emoji/组合字被拆坏 | 按 Unicode grapheme 分组，Latin/RTL 词组保持语义单位；阿拉伯等仍须真实看字形连接和方向，分组通过不证明排版正确 |
| 离线预加载脚本插错位置 | bundle 中也有字面量 `</body>`；插入真实外层 HTML 的结束位置，不能 replace 第一个匹配 |
| 竖屏露出图层边缘 | 单一 cover 裁切不能适应原场景布局；重排人物/帘幕/文字走廊，检查背景与裁切接缝 |
| 采样图看不出运动 | 均匀抽帧丢掉启动、峰值、停顿；补看原视频和局部连续帧，记录实际时间，不靠帧号猜速度 |

## 视频输入同样遵循证据链

若用户提供视频取帧 ZIP，读取其中的 `reference.json`、全部帧和标注，并观看原视频。写出：时间段 → 观察到的文字/镜头/光效关系 → 推测实现 → 适配任意歌词的规则 → 仍缺证据。必要时补抽动作起/峰/停/消失的帧。不可把视频铺底称为重建渲染器，也不可声称从画面恢复了原源码。

## 猫与蜜蜂：从移动字幕到留下字迹

素材3444535389是黑底白线的猫追看蜜蜂。初版只是连接测试；v0.2从蜂的位置发射后落入固定行位，v0.3沿当前飞行弧长拖着文字走并裁去旧尾部。用户明确否定：字应停留在生成附近、只做局部浮动，到下下句开始出现时才渐隐。前两种方案虽然通过运行与碰撞测试，语义仍错。

v0.4将三件事分开：逐字/整句/组句入场；出生邻域与固定锚点；N+2触发退场。逐字模式依据当句实际发射位置确定乐句邻域和轻弯字位，先为整句预留可读空间，再按每个字的时值在原位描显。新字不从蜂尾跳到槽位，已出现的字也不移动去给新字让路。此处保留字迹与阅读连续性优先，不要求每个锚点恰好等于蜜蜂坐标。

一个失败尝试把每个字独立放在最近空位：两句驻留后形成乱字堆，虽不重叠却无法连贯阅读。因此改为生成前为完整乐句预留空间。字号或画幅变化时可重建锚点，普通播放/seek时不能重排。

速度仍由字词时值平滑驱动，间奏慢游；文字保留期间与蜂的移动脱离。晚起点的首字决定该句实际开始出现时刻，空白行不推进N+2，最后两句保留到场景结束。三种形式的精确定义与验收见[歌词释放语法](lyric-release.md)。

## 夜莺 v1.1：窗边微光组句

再次重制3448877775时保留原画、网格、窗帘与夜景层次，替换早期持续向外流走的文字。MCP按冷蓝夜景、柔光和静谧人物选择assemble：字词独立点亮并从小范围错位聚成句子，随后留在出生邻域轻浮，到N+2再淡出。每句只有短暂少量音符，不能每字永久贴同一个符号。

发声点与场景共用坐标变换，并复用人物头部的呼吸/转动公式；只在出生时采样，不把这些动作继续施加给已留下的字。横屏预留头部禁入区，竖屏把文字安排在人物上方。最后两句驻留，人物在纯音乐段继续轻呼吸。

历史原型的两包共享了时序、锚点和三种入场，各自保留发射者、配色、人物禁入区与艺术选择。技能只分发方法与代码，不包含原画素材。

## 夜莺 v1.2：用户否定“微光字幕”，改为轻哼字流

v1.1虽正确保留文字至N+2，却把组句理解成水平居中的排字。用户指出仍像普通字幕，要求“像女孩轻哼出的音符，从她附近自然流淌、错落成句，生成后留在附近轻轻浮动”。这说明出生、驻留正确仍不足以证明艺术语义正确；不能拿碰撞测试或固定锚点替代这一判断。

本次把句子的空间形状和释放节奏一起重做。独立flow模块按实际字形宽度排出上扬的气流字带，词间时值空隙与标点产生呼吸间隔，稀疏句有轻拱、密集句更舒展。起点靠近女孩，短暂的少量微光连接头部发声点和第一批字；文字按时值比例分布在至多2.4秒的组句窗口内逐渐浮现，只在出生锚点附近完成局部聚拢。整句不再以字幕矩形占位；按每字完整入场包围盒预留，避免旧句逼新句跳进远处固定槽。

生成与驻留严格分开：已经留下的字不会随人物、句子进度或气流继续移动；每字低速、小幅浮动，直到N+2开始放出才统一渐隐。长句换成相续的错落气流段，完整保留，必要时缩放；连接书写文字保持整段字形，视觉花样让位于连写和方向正确。

借用绘光的独立字词点亮与局部聚拢、凝彩的乐句方向连续性；不照搬绘光的整齐窗格，也不复制花火的强爆发。视觉验收应看“发声点→第一批文字→整句形成→留声→N+2退场”的连续事件，额外看两句共存时是否仍能顺着读。技术验收依然不能宣告用户审美通过。

## 夜莺v1.3：弯曲字幕仍然不是从人物流出

v1.2把字位改成气流曲线，但只在各自终点上下十余像素渐显；从女孩向外飞的是装饰光点。用户再次否定：“字要真正从女孩附近随轻哼流出来，再停在对应位置轻浮，不要直接在远处依次亮起”。错误在动作因果，不在曲率参数。

修正将字形本体纳入输送。每个字从自己的发声点快照附近可见出生，沿冻结的贝塞尔路径运动到已预留的留声位置，减速后切换到局部漂浮。多个新字可以处于运输中，先到的字已经停留；所有字的退场仍由N+2统一触发。原有曲线排版只决定“停在哪”，不再负责伪装“从哪里来”。

实现新增journey.mjs，仅在布局编译时选择路径与速度，普通帧按绝对时间求值。必须分开记录运输中的穿行、完整画布边界和驻留文字不重叠，不能把旧版针对固定字位的验收原样套到有真实运输的新实现。
