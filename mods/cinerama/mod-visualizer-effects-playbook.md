# 歌词特效模组开发手册（沟通经验）

从「巨幕 Cinerama」模组的开发过程里抽出来的经验，供**后续开发新特效**时直接当提示词参考：
发起需求时按第 1 节把信息一次给全，开发过程按第 2/3 节执行，出问题先查第 4 节的三个问题与症状表，
写自带面板前先过 4.7 的六条硬规则，动手前先想 5.1 的改动边界。
目标是压缩「提需求 → 猜意图 → 返工」的往返轮数。

- 模组系统本身（manifest、信任、IPC、visualizer 契约）：`mods/README.md`
- 内置模式的组织方式：`src/components/visualizer/README.md`，逐模式文档如
  `src/components/visualizer/tempera/README.md`（本手册的写法就是照它来的）

---

## 1. 提需求时一次性给全的六件事

缺任何一件，基本都会多一轮往返：

1. **参照物 + 要抽哪几组效果。** 给截图/视频帧是必要的，但不够——必须指明「从这张图里抽出哪几组」。
   只给一张演出截图，对方会按自己的理解分组，很可能不是你想要的那几组。
2. **阶段：脚手架还是细节。** 「先搭可编排的骨架、细节不实现」和「直接落地细节」是两种工作量。
   明确阶段，脚手架阶段就别再追问「为什么没有逐字动画」。
3. **反例（不要什么）。** 反例比正例更能省轮数，实测有效的表述：
   「不要半透明胶带」「角度和位置要错开，现在没错开」「数量似乎太多了」
   「设置要放在歌词动画设置里模式下方，不要放在模组面板」。
   这些在事后提，等于一次返工；在需求里提，一轮就到位。
4. **设置放在哪、要不要持久化。** 三种位置（见 4.6），需求里要指明。
5. **验收方式。** 能强制验证就不要靠随机碰到：例如「要能强制只显示某一组」——
   巨幕给了样式的**三个概率权重**（大字报／小字报／斜切丝带各 0~1），
   怀疑某组没出现时把另外两项拖到 0 就能逐组验证；叠加项同理（跑马灯带 关／自动／双带／四边）。
6. **控件的语义与默认值**（最容易事后返工的一条）。同样一句「设置里能选效果」，
   至少要先定死四件事：**本体是"多选一"还是"各自一个概率权重"**、**可叠加的项是不是单独的档位**、
   **「自动」的作用域**（只管排版，还是连叠加项一起随机）、**每个档位的默认值**。
   拿不准就**一次问清**（把候选做法和代价列成选项），比事后改省一轮。
   教训：**能表达成权重的就别做成档位**——「自动」和几个显式档位说的是同一件事，
   而权重还能顺带表达「某档多一点」这种意图。
7. **分组的口径是「用户要调什么」，不是「代码里有几条轴」。** 巨幕的面板从「按三条轴分四组」
   改成「五组小节」（内容与概率 / 歌词处理 / 文字样式 / 跑马灯带 / 斜切丝带），判据只有一条：
   用户想调一件事时，能一眼找到那一组。所以命名也照用户的说法（「带速」「字号」「字距」），
   不照代码里的变量名。**一屏二十多个旋钮不分组就分不清哪几个是一伙的。**
8. **不要为同一件事留两个旋钮。** 巨幕曾经同时有「大字报字号」与「小字报字号」两个倍率，
   而它们的作用机制其实不同（一个乘在切分阈值上、一个乘在最终字号上），说明里怎么写都别扭。
   现在是一条共用的「文字样式 · 字号」，语义唯一、乘法只有一处。判断标准：
   **两个旋钮在用户脑子里是不是同一个量**——是就合成一个，哪怕代码里走的是两条路。
9. **删掉一个旋钮时，先看它的"档位"还有没有别的表达方式，并且要确认那条替代路径真的通。**
   `heroScale > 1` 本来是「多切一块」那条路径的开关。合并成统一的「文字样式 · 字号」之后，
   这条路径**不会**被倍率自动触发（`fitVh * Math.min(1, scale)` 里那个 scale 已经恒为 1）——
   文档曾经把它写成「由倍率自己触发」，实际拖大到今天仍是「把最终字号再乘一次、可能顶破
   安全区」。删旋钮之前先验证被删的行为落到了哪里，别拿注释里的假设当事实。

## 2. 结构：照 sonnet 的分层拆，别堆在一个文件里

可按需要裁剪，但**边界**要保持：

| 层 | 职责 | 是否碰 DOM |
| --- | --- | --- |
| 确定性随机 | FNV hash + 相邻不重复抽取；seek/重建不洗牌 | 否 |
| 切分 | 一句话拆成带时间窗的 units | 否 |
| 排版 | 落点/字号/字距表 | 否 |
| 动画 | 统一的 enter/hold/exit 包络帧 | 否 |
| 视觉处理（样式 + 叠加项） | 排版本体的几何参数；叠加元素/特效的参数与开关 | 否 |
| 编译 plan | 每条歌词一份 plan，多轴各自抽取 | 否 |
| 渲染 | 建层 + 层内逐帧运动 | **是（唯一）** |

硬约束：

- **先分清「排版本体」和「叠加项」**。本体是**多选一**（巨幕：大字报／小字报／斜切丝带，
  各自一个概率权重、每句按权重抽一个），叠加项是可以往上叠的元素（跑马灯带），
  后者不能塞进本体的选项里——塞进去就只能单独出现，「大字报 + 跑马灯」这种组合永远做不出来。
- **每个样式都要有 `supports` 条件**（大字报要求行内有字、丝带要求这一行排得出内容）。
  条件不满足的不进随机池，并且要有一个无条件的兜底样式（巨幕是小字报）——
  限制本身就是效果的一部分。
- **组合要有规则**。巨幕：跑马灯带可叠在大字报/小字报上，斜切丝带不与它组合（丝带本就占满屏）。
  规则写在解算层，UI 上写进分组提示，别指望用户自己猜。
- **抽取要加权**。等权时朴素样式会吃掉一半以上的行，整首歌看下来就是「单纯出字」
  （巨幕实测：等权 55% 朴素 → 加权后 15%）。
- **units 必须先进 DOM**，逐段效果才有下手的地方；在整行直出的现状上加逐字细节是返工。
- 渲染层唯一碰 DOM；行级包络打在外层容器、层内运动由各组自己驱动，两边**不写同一批属性**。

## 3. 交付前自检（最能省轮数的一节）

别用「应该可以」结案，每条都给实测数据：

1. **语法**：`node --check` 每个 `.mjs` / `.cjs`。
2. **manifest**：走加载器校验 `validateManifest(require('./mod.json'))`（在 `electron/modSystem/manifest.cjs`），
   顺带确认 `visualizers` 解析出来的条目数。
3. **DOM 桩冒烟**（无需浏览器）：模拟 `document.createElement`（元素桩带 `style/children/append/remove`）
   后 `import()` 入口并 `mount`，逐项验证：挂载、换句、**强制每种样式 × 每个叠加档位构建**、
   逐帧 update 有变化、切换设置立即重建、`getSettings`/`getModulation` **缺席**时仍工作
   （导出窗口场景）、dispose 清零。
   带自带面板的模组还要验：面板在宿主 DOM 里挂对位置、模式不对时隐藏、宿主重绘后补挂、
   宿主没有挂载点时只是不出现（不抛错）。
4. **分布统计**：40 行样本打印各组的命中次数与「相邻行是否重复」，确认没有组始终不出现。
5. **碰了 `src` 就跑 `npm run typecheck`**（模组文件是 JS 不检查，但 app 侧桥接是 TS）。
6. 几何类效果额外验证「错开」：角度是否有重复、位置最小间距、数量是否在规格区间内。
7. **自带面板三个动作各验一次**（只在浏览器里能验，别省）：
   切到别的分区（面板要消失）→ 切回来（要插回原位、值还在）→ 换亮/暗主题（配色要跟着变）。
   再切一次模式：不是巨幕时面板必须隐藏。
8. **新增旋钮先归类，再实现**：① 建层时写进 CSS / 读一次（字号、字距、行距、斜体、填色、
   运动幅度、**边线辉光与文字辉光**）→ 必须进 `cineramaStructureSignature`；② **编译期**抽的权重
   （样式、排版落点）→ 进 `cineramaStyleWeightSignature`（重编 program，**不进**结构签名，
   否则每次拖动都白重建一遍当前层）；③ 连续量（带速、边线流速、丝带漂移、落位节奏）→
   每帧现读，两个签名都不进。分类错了的表现就是「拖了没反应」或「每拖一格重建一次整层」。
   容易判错的一处：**「辉光」看着像连续量，其实是建层时写死的 `text-shadow` / `box-shadow`**，
   所以两个辉光旋钮都归 ①。
9. **每个档位都要能触发重建**：切带型、拖样式权重后画面应**立即**变（不是等下一行）。
   没立即变 = 旋钮没进 `cineramaStructureSignature`；**样式权重**还要额外确认它同时触发了
   program 重编（`cineramaStyleWeightSignature`）——样式是编译期抽的，只重建当前层的话
   后面那些行拿到的还是旧权重。

## 4. 症状 → 根因 → 处置

按看到的现象查，比按模块查快。查之前先过一遍**三个问题**，多数「UI 看着不对」的 bug 都卡在
这三者不同源上：

1. **谁渲染？** 界面上的这块 UI 是宿主渲染的，还是模组自己插的（两组同名旋钮往往就是两个人各渲染了一份）；
2. **谁存储？** 拖一次，值写进了哪个 key / 哪个 store；
3. **谁读取？** 渲染层每帧读的是不是上面那个源。

**渲染方 → 存储方 → 读取方**必须闭环。用户报的是现象（「多了一组」「第一组没反应」「切走没隐藏」），
别按现象打补丁——把多余的那组删掉，剩下那组可能照样读不到值。

| 症状 | 根因 | 处置 |
| --- | --- | --- |
| 动画模式列表里显示内部 id（`cinerama.cinerama-screen`） | i18next 默认 `nsSeparator: ':'`，`ui.modVisualizer.mod:<id>:<viz>` 在查词典**之前**被拆掉命名空间，`parseMissingKeyHandler` 只拿到残片，`labelFallback` 判定失效 | labelKey 里把 mode 按 `.` 拼接（`src/mods/modVisualizers.tsx`） |
| 改了文件没生效 | 加载器只给**入口** URL 加 `?v=<摘要>`，子模块是裸相对路径，留在浏览器 ES module map；面板「重新加载」只会重 import 入口 | Ctrl/Cmd+R 重载窗口或重启应用 |
| 版本号/命令对不上，效果像上一版 | 目录扫描 `userData/mods`（打包版优先）与仓库 `mods/`（开发版优先）**同 id 只认先扫到的** | 面板版本号 + 主进程日志（带版本与命令名）是唯一可靠判据；删掉 `userData` 下的旧副本 |
| 内容改了之后模组保持禁用 | 摘要失配会**撤销信任**，必须重新确认 | 重新启用并确认；别只点「启用」 |
| 整屏冻住，而不是某一句没效果 | `paint()` 里抛异常会被 MotionValue 订阅链吞掉并**断开订阅** | 建层与逐帧更新都要 try/catch 兜底（退化成朴素整行 + `console.warn` 带 `[modId]` 前缀） |
| 设置看不到 | 自带面板是在 `mount` 里挂的，所以要先选中该模式；挂在宿主设置面板里模式选择器卡片的下面，要往下滚 | 见 4.6；面板一直不出现时看 DOM 里有没有 `data-cinerama-panel` 节点，同时确认锚点 `[data-mod-visualizer-settings-slot]` 在不在 |
| 出现两组同样的设置，其中一组拖了没反应 | manifest 声明了 `visualizers[].settings`，宿主照它又渲染了一份；**无效的那组**写的是对面不读的存储 | 两组只能留一组：自带面板的模组不声明 `settings`（见 4.7 规则 2）。别只把多的那组删掉——先确认**读的一方**到底读谁 |
| 切到通用/背景分区后自带面板还在 | 面板是手动插进 DOM 的，宿主不会替模组收走；可见性判定「判不出来就显示」会把它留在无关分区 | 判不出来按隐藏处理；定位不到锚点/卡片时直接把面板从 DOM 摘下来（`hostPanel.mjs` 的 `detachPanel`） |
| 面板在亮色主题下是一块黑卡片 / 换个主题不变色 | 写死了深色，或引用了宿主根本没定义的变量（巨幕曾用 `--player-panel-bg`，它不存在） | 只用 `--bg-color` / `--text-primary` / `--text-secondary`，用 `color-mix()` 混色，并留中性灰兜底（见 4.7 规则 5） |
| 多选一按钮的配色和内置模式的 pill 不一样 | 拿 `--text-primary` 当强调色；宿主选中态用的是 **accent**（`--text-accent`）+ inset 内阴影 | 照 4.7 规则 5 的规格表改：accent 描边 + 内阴影 + 14% 淡底 |
| 「默认」按钮位置/样子和宿主不一样 | 自己放了一颗底部下划线按钮 | 挪到卡片头部右侧，做成 pill + 回环图标（见 4.7 规则 5） |
| 一屏旋钮分不清哪几个是一伙的 / 同一个量有两个旋钮 | 分组照代码里的轴分（一条轴一组），命名照变量名；或者历史上给两个样式各留了一个同类倍率 | 分组照「用户要调什么」（见 5.1 里第 7 条的判据表），命名照用户说法；**同一个量只留一个旋钮**，两条实现路径在渲染层合并成一次乘法 |
| 备注里出现 `**` 之类的标记 / 一条备注占三四行 | 备注是照 Markdown 文档的写法写的，而它走 `textContent` 直接进 DOM | 备注只写纯文本、压到一行左右（中文 ≤64 字、英文 ≤240 字符），判据见 4.7 规则 8；`writes knob hints as plain one-liners` 锁住 |
| 拖了一个旋钮画面不动 | 它既不在结构签名里（要立刻重建），也不在权重签名里（要重编 program），又不是每帧现读的连续量 | 三选一：建层时写进 CSS / 读一次 → 结构签名；编译期抽的权重 → 权重签名；速度、漂移这类连续量 → 每帧现读（`test/unit/mod-system/cineramaTextStyle.test.ts` 锁了这个分类） |
| 旋钮**只有一部分行程**有反应（拖到某一段就不动了） | 同一条 CSS 里写了两个不同尺度的边界（`clamp(20px, …vh, 236px)`：vh 跟着屏高走、px 是常量），屏体一大那条 px 边界就抢先接管 | 解算层给的量本身已经钳过（如 `maxFontVh`），渲染层**只兜像素下限**、不写上界；凡写 `vh` / `cqh` 的地方不要并列绝对 px 上界 |
| 面板和内置模式的设置卡片长得不一样（像卡片里套了一块） | 挂错了节点：插在锚点**内部**等于嵌在模式选择器卡片里，上下留白、圆角都对不上 | 挂到模式选择器卡片的**下一个兄弟位**，与内置 `renderSettingsPanel` 同父同层（见 4.7 规则 3） |
| 切了档位要等下一行才生效 | 档位没进结构签名，渲染层不知道要重建 | 所有「建不建这一层」级别的档位都进 `cineramaStructureSignature` |
| 纵向留白被吹起来 / 元素位置怪 | 百分比 padding 按**宽度**解析（2.4:1 的屏上尤甚） | 纵向 padding 用 `em` |
| 位移方向不对 | `transform` 里 `translate` 写在 `rotate` **之后**会变成沿局部坐标 | 屏幕方向的位移写在 rotate 之前 |
| 循环滚动的文字「一次重复后位置跳变」 | 回绕位移按**份数**算（`100/份数`%），份数就是回绕周期；只有 1~2 份时一次重复等于整条宽度，滚过一格就把整条文字推走一格宽的空白 | 铺满到**至少 3 份**，并且量 `scrollWidth` 而不是按字数估（字数估不准，中英混排/字距/字体回退都会偏） |
| 循环带子初始时没超过屏幕边缘 | 同上：按字数估的重复次数不够，或目标宽度没乘安全系数（元素旋转后水平覆盖宽度会变） | 量真实宽度 × 安全系数；只在**量得到宽度的第一帧**量一次（建层时 `clientWidth` 是 0），逐帧量会触发同步布局把整屏拖成掉帧 |
| 「一次出的词出屏了」 | 字号是按「整行/固定字数」定死的，或倍率在**钳制之后**再乘，把已经贴边算出来的尺寸又放大一次 | 按词分词 + 每块各算一个安全字号取最小；倍率乘在**切分阈值**上（装不下就多切一块），不要乘在最终字号上 |
| 一句里连着几次闪现长得一模一样 / 落位后是块死字（观感单薄） | 块级动作同构：入场只有 fade + 一个固定缩放、块间字号统一、挂住期间完全不动的变数只剩斜体 | 块级三处，都按 `(seed, 块序号)` 抽、seek 稳定：① 字号池 ±5%**相邻不重复**（上限＝该块自己的安全字号）；② **蒙版填色**：概率按块的**字数**拟合（见下两行；两层互补、共用同一个行程 `u`）；③ **持续运动**：**只有没填色的块**按**权重**抽（权重 **2 : 2 : 2 : 1 : 2 : 4（和 13）**＝推近/拉远/横移/**摊开**各 2、纵移 1、still 4——**竖直运动只此一档**，放大/缩小不再带纵向位移，摊开也不带位移；线性行程、位移**收到正中**、幅度按窗口长度归一，缩放最高到 1.5）。**摊开**＝一边放大到 1.3 一边把字距加到 0.15em（字距/缩放共用一个行程；字距加在末字之后会让居中排版左偏半个字距，所以要配一个等量的负 `margin-right` 抵掉）。**填色与运动不重叠**：会移动/缩放的块不填色、做填色的块原地不动（一块只有一件事，两者**此消彼长**）。入场仍是 0.92→1，与持续运动相乘（`cineramaHeroMotion.test.ts` / `cineramaHeroFill.test.ts`）。幅度与权重都是常量、不进面板 |
| 填色落在一个字的块上（「的」「了」这种虚词独自一块）——扫描没有过程、只闪一下，像故障 | 触发概率是**定值**、与块长无关：短块与长块同概率，而 CJK 句子里一个字的块很常见（实测占 ~1/4） | 概率按块的**字数**拟合（`heroFillChance`，锚点在 `TUNING.hero.fillChance`）：**1 字 0%｜2 字 2.1%｜3 字 6.7%｜4 字 11.3%｜≥5 字 13.3%**，曲线是 `cap × smoothstep((字数−1)/(5−1))`——两端一阶导为 0，所以 1 字稳在 0、5 字稳在 cap，不会在锚点上跳变。12 句 CJK（10~13 字/行、默认并块概率）：长块少、短块多，整行平均触发 ≈ **5.6%**（`cineramaHeroFill.test.ts` 锁了锚点、单调性、端到端闸门） |
| 七项动效的概率「说不清」/ 改了填色上限后其余几项悄悄失衡 | 填色上限（在 `TUNING.hero.fillChance.cap`）与运动池权重（`HERO_MOTION_POOL`）是**两个地方**，但口径上它们是**同一个式子的两个未知数**：`cap = (1 − cap) × w_push / W` | 口径：**填色上限 = 放大 = 缩小 = 横移 = 摊开，纵移是一半、静置是二倍**（七项和＝1 → 每份 **2/15 ≈ 13.3%**）→ 池子取整数权重 **2 : 2 : 2 : 1 : 2 : 4（和 13）**、`cap = 2/15`（填色**只在这条曲线上**，短块本来就低于这几者）。**加一档 weighted 2 就得把 `cap` 从 2/13 挪到 2/15**——每加一项，所有已有项的份额都会被摊薄，只改一头必然失衡。改一个必须连着改另一个；`cineramaHeroFill.test.ts` 的「seven-way recipe」按 300 个到上限的长块实测这七项占比 |
| 填色把**辉光**裁断了（填过的地方有光、没填的地方没光，交界处一道硬边） | 影子画在被蒙版裁剪的那一层上：`clip-path` 裁的是**整层**（字身 + 影子），所以填色推进到哪儿，辉光就在哪儿断 | 影子单独一层、**永不参与蒙版**：`color:transparent` + 同色 `text-shadow`（透明字身只挡字身，影子照画），放在最下面；被扫的实色层卸掉自己的影子（`text-shadow:none`）。不填色的块没有蒙版，仍用自带影子的单层（一个节点都不多）（`cineramaHeroFill.test.ts` 断言辉光层从头到尾没有 `clipPath`、实色层 `text-shadow:none`） |
| 填过的那一段还挂着描边 / 填色与描边不同步 | 两层各裁各的（位置/方向写反、各用一套进度），或者描边层没做互补；另外 `text-shadow` 是**继承属性**，不显式关掉描边会跟着发光 | 两层**互补**、共用**同一个** `u`：实色层 `inset(0 剩余% 0 0)`、描边层 `inset(0 0 0 已填%)`（竖直方向把首尾两个值换掉）；描边层显式 `text-shadow:none`、宽度是常量 `outlineWidthEm`；蒙版量的是**字身**不是整屏（两层的盒子用静态 `translate(-50%,-50%)` 收紧到字上，否则两头空扫）；**不填色的块连描边层都不建**、实色层也不裁（不写 `else` 清场——那些块压根没写过 `clipPath`）（`cineramaHeroFill.test.ts`） |
| 大字报出字明显滞后（歌词时间戳却是正常的） | 逐块闪现的落点是「歌词窗口 ÷ 块数」**均分**的——均分只在词距均匀时才对；唱得快而这一行的显示窗口还长着一大截时，后面的块一路滞后（5 块实测差到 **1.60s**） | 每块以**自己第一个字素**的时刻入场（`resolveCineramaSegmentSpans`，与 units 同一套对位；块尾被裁掉的空白要跳过）。块间不收口：下一块的起点就是本块的终点，最后一块顶到歌词窗口终点。**对位从不整体放弃**（字符对不上就按顺序继续，与宿主 `findGraphemeSequence` 的口径一致）；只有块的起点没能严格递进（API 没给出可用的词级顺序）时才按**宿主自己的那条口径**摊开（`cineramaHeroTiming.test.ts`）。通用口径：**凡是「按段出词」的落点都要按段自己的字素对位，不要摊窗口** |
| 切分把词切碎了（「摊开」→「摊」「开」） | 按固定字数切 | 用 `Intl.Segmenter(word)`（用户存过的 `wordSegments` 优先），空白折进前一个词、标点粘在前一个词上 —— 与凝彩同一口径 |
| 胶带/条带的宽度和字号一起变大 | 厚度是文字的 `padding`，字号一大整条就跟着变粗 | 厚度与字号做成**两个独立的量**（各自一个 vh 区间） |
| 叠压读成 z 轴排序（「前面的亮、后面的暗」） | 明暗是按**层序**给的，读出来是排序而不是材质 | 明暗做成**元素自身的渐变**（稍亮一段 + 稍暗一段），叠压关系交给投影（`box-shadow`）表达 |
| 效果「太规矩」「像栅格」 | 角度等差 + 位置均铺 + 小抖动 | 角度从离散档位**不重复**抽取，位置先均铺再整体乱序 + 大抖动 |
| 想要半透明但做不到 | 主题色是任意格式的 CSS 字符串，做不了可靠 alpha | 用 `filter: brightness()` 做阴影层、实底 + 主题背景色反白，靠叠压而非透明度分层 |
| 观感「只是在出字」 | 朴素组占比过高 / 组权重等权 | 加权抽取 + 统计分布确认 |
| DevTools 里一堆无谓的样式失效 | 逐帧重复写相同字符串 | last-value 缓存（`createStyleWriter`），值没变就跳过 |
| 改了配色，某一档就是不变（四边跑马灯带的字） | 那一档的节点不是 HTML：SVG 的 `fill` 独立于 `color` 且缺省 **black**，外层 div 上写 `color` 传不进 SVG，照抄双带的写法就等于没改 | 在 SVG `text` 上显式 `fill:currentColor`；写断言时看**那个节点自己**的样式，别只搜整棵树的 cssText 里有没有 `color:`（`test/unit/mod-system/cineramaMarqueeFrame.test.ts`） |
| 循环带一侧先空出一截、然后忽然补上字 | 位移一次是**一份**宽，而内容没有比盒宽多出一份（份数按「盖住盒宽」算、还被封顶在 6 份）；内容只在份与份**之间**插分隔符，元素宽度不是整数份，绕一圈差一点、累积起来同样露白 | 内容按**整数份、每份以分隔符收尾**铺（`repeatBandText`），位移写成 `-100/份数 %`；内容起点贴盒左沿（不要 flex 居中）；份数满足 `N × 一份 ≥ 盒宽 + 一份`，上限只防跑飞（`test/unit/mod-system/cineramaMarqueeBands.test.ts`） |
| 上下两条带里有一条的字「还没走到屏沿就没了」/ 某一侧固定空一截 | 下带整体 `rotate(180deg)`，映射是 `x → W − x − t`：**左沿会翻到右边去**，照抄正片的位移符号时内容起点被甩进盒内（长句的一份 ≈ 整屏，整条带会整段空掉） | 镜像那条的位移往前挪一格（`m + 1`，区间 `[0, 一份]`），覆盖条件才和正片一样成立；顺带保住「上下反向」（同一个 `t` 在屏上反向）。镜像那条的断言要换算回**屏幕方向**再比，别直接比变换值（`cineramaMarqueeBands.test.ts`） |
| 下带的译文是**倒的**（上原文下译文时读不了） | 下带的 `rotate(180deg)` 是「同一条带绕屏一周」的错觉用的——同一个行程在屏上反向 + 字读向反过来，**只有上下跑同一份文本时**才成立 | 文本不同就不翻字（`rotate: 0`），对开改由**行程取反**承担（`reverse` → `−1 − m`，仍在同一份的区间里）。判定在 `cineramaTreatment.resolveCineramaMarquee`（`mirror = bottomText === topText`）；不翻字那条**不能**跟着走 `m + 1`（那是翻边用的，会把内容推出盒外），也不能走 `m`（同向就丢了对开）（`cineramaMarqueeBands.test.ts`） |
| 切场景时丝带「停了几帧」、然后下一屏刷出来 | 有运动的层被当静态层处理：① 丝带位移预算只算到**行窗口末尾**（`pxPerSec × span`），而窗口结束后它还在屏上挂着（空档 `hold` 最多 0.6s、转场交叉 0.14~0.28s）；② 退出方一律冻结 | 位移预算改成「行窗口 + `travelTailSec`」，内容余量照旧兜底；退出是否继续 `update` 按**层有没有运动**定（`cineramaOutgoingKeepsMoving`：丝带继续，大字报那类仍冻结）（`cineramaRibbonTravel.test.ts`）。通用口径：**凡是有持续运动的层，退出那一段都要继续跑**，冻结只对「越界即全透明」的层成立 |
| 跑马灯带的辉光「始终是浅灰色」，换「边线色彩」没反应 | 两个原因叠在一起，都在**辉光只有一样「弱」的表达**上：① 三层阴影的浓度直接乘辉光强度，缺省 0.3 把亮芯压到 30%、往屏面那一层压到 5%，屏上只剩一根读不出颜色的灰线；② 亮色主题那一档写死 `rgba(0,0,0,α)`，色轴被整条丢掉。第三样是感知上的：带上的字继承了正文的 30px 满浓度同色辉光，一圈密排小字被自己的光糊住，屏上最亮的那圈光**不是**边线 | 浓度改走 `alphaFloor + (1 − alphaFloor) × 强度`（半径仍线性乘），亮芯的半径提到与带内字号同一个量级；亮色主题的槽色改成「色轴压暗到 `darkMix`」而不是中性灰；带上的字单独一份弱影（`bandSkinOf`，半径按**带内字号**取比例）——「亮」由边线那道灯承担，不由每个字各带一圈光承担。断言从 `CINERAMA_TUNING` 推期望值，不写死数字（`cineramaMarqueeFrame.test.ts`） |
| 跑马灯带上文字的运动速度「跟歌词长短走」，短句像爬、长句读不清 | 位移写的是**一份**的百分比（双带 `translateX(-100/份数 %)`、四边 `startOffset`），所以带速实际上是「每秒走几份」，而一份的长度完全随文本走（同一块屏上 4 字一份 266px、48 字符英文一份 1452px，屏上速度差 6.7 倍） | 速度改写成**「每秒走几屏」**（`screensPerSec`，由 seed 抽），周期 = `一份长度 ÷ (屏宽 × 每秒几屏)`——**文本长度只出现在分子**，正好把内容依赖抵掉；`marqueeSpeed` 是它的倍率。各种长度的句子（160~1452px 一份）在屏上的速度于是相同（`cineramaMarqueeBands.test.ts`）。通用口径：**「速度」的量纲必须钉在屏上，不能钉在内容上** |
| 带上文字的同色辉光「拖了没反应」/ 一直看不到光 | 语法错，不是强度错：`text-shadow` 只收**三个长度**（`offset-x offset-y blur`），**没有 spread**。写成 `0 <下落> 0 <横半径>px`（四个长度，抄的是 `box-shadow`）会让**整条 `text-shadow` 声明被丢弃**——连带紧随其后的同色光一起，宿主的 `getComputedStyle().textShadow` 于是恒为 `none` | 去掉那个不存在的 spread，改成 `0 <下落> 6px rgba(...)`（`dropBlur` 挪到 blur 位）。再挂一条断言锁**长度只有三个**（`cineramaMarqueeFrame.test.ts`）——只断言「字符串里有这层光」是锁不住的，字符串里一直都有、是浏览器丢掉了。通用口径：**CSS 值能不能被浏览器接受，要读 `getComputedStyle`，不能只读自己拼出来的字符串** |
| 正文压在跑马灯带上 | 排版层不知道带占了屏沿哪几条边；带的厚度写的是**屏高的百分比**，四边环的左右那两道还得折成屏宽（`bandPct / aspect`），各算各的必然对不上 | 一处解算 `resolveCineramaBandInset`，两种让法：小字报取「排版轴留白 vs 让开量」的大者当内边距，大字报居中排 → 收窄可用框（竖向 ÷ 行高、横向扣掉左右带厚），且**同一个可用框**同时用于「能并多大块」与最终字号（`cineramaBandSafeArea.test.ts`） |
| 带子里的字糊在正文上（字与字相踩） | ① 让开量只给了一个带厚，正文紧贴带子内沿，而带上的字自带一圈同色辉光；② 竖向内边距写的是 `%`，而百分比 padding **四个方向都按宽度解析**——屏幕越窄「按高度看」的留白越小，最后小于带厚 | 让开量 = 带厚 × 1.25（`TUNING.marquee.safeClearanceRatio`，把辉光也留出去）；内边距改 `cqh / cqw`（屏体是 size container，与带子的 `height:%` 同一把尺子），`vh / vw` 只作老宿主兜底（`cineramaBandSafeArea.test.ts` 锁了单位） |

### 4.6 设置放哪

| 位置 | 机制 | 适用 |
| --- | --- | --- |
| 宿主界面上自己插一块面板 | 挂到**模式选择器卡片的下一个兄弟位**（宿主渲染内置模式设置面板的同一位置，外观才对得上）；定位靠宿主锚点 `[data-mod-visualizer-settings-slot]`——属性值给当前 mode id（模式判定不靠文案），从它 `closest('.rounded-[24px]')` 找到卡片；定位不到卡片就把面板塞进锚点，锚点也没有则**不挂**（`cinerama/hostPanel.mjs` 轮询补挂） | **用户首选**：视觉/效果参数，宿主只需留一个空锚点 |
| 模组面板命令 | `api.commands.register` + `modulate`/`live` → `props.getModulation()` | 实时倍率，不要求持久化 |
| 无设置 | 只靠 manifest 常量 | 原型期 |

自带面板是**模组侧**的实现：宿主的全部配合就是一个空锚点
（`<div data-mod-visualizer-settings-slot="<当前 mode id>">`，宿主侧见
`src/components/visualizer/ModVisualizerSettingsSlot.tsx`），没有任何模组专属的接线。
锚点缺席（旧宿主）就**不挂**，不猜位置——文案定位那条回退没有可靠依据，走进去既挂不上、
又会每 400ms 把面板摘一次。宿主换布局的正确结果是「面板不出现」而不是报错，
见 `hostPanel.mjs` 顶部的说明。

### 4.7 自带面板的六条硬规则

自带面板之所以容易出事，是因为它是**模组手动插进宿主 DOM 的非受控节点**：宿主不知道它存在，
不会帮它收尾，也不会替它配色。把它当「借宿」而不是自己家，下面六条就都说得通：

1. **值要落在模组自己每帧读得到的地方。** 巨幕是 `cineramaSettings.mjs` 的共享单例
   （面板写、渲染层每帧读**同一个对象**，所以拖动下一帧就见效）。只写不读 = 面板无效，
   而且是那种「UI 一切正常、就是没反应」的无效。
2. **不声明 manifest 的 `visualizers[].settings`。** 宿主会照那份 schema 再渲染一组表单，
   于是同一个模式出现两组旋钮，而宿主那组写的存储模组不读。
3. **挂到与内置卡片同层的位置**：模式选择器卡片的**下一个兄弟位**（宿主渲染
   `renderSettingsPanel` 的地方）。插在锚点内部会变成「卡片里套一块」，圆角和留白都对不上。
4. **判不出来就隐藏，定位不到就摘下来。** 宿主切分区后不会替你收走它——
   留在原地就是「巨幕设置出现在通用分区」。摘下来不丢状态，回到该分区会自动插回。
5. **配色与控件规格照抄宿主**。主题变量只有三个可用：`--bg-color`、`--text-primary`、
   `--text-secondary`，外加**强调色 `--text-accent`**（`buildAppStyle.ts` 写的 accentColor）。
   混色一律 `color-mix()`（主题色是任意格式的 CSS 字符串，模组侧做不出可靠的 alpha 化），
   变量缺席留中性灰兜底。写死深色则亮色主题下是一块黑卡片。
   宿主的控件是 React 组件，**复用不了**（拿不到它的 onClick，它重置的也是内置模式自己的
   tuning store），所以做法是照抄它的尺寸与配色：

   | 控件 | 宿主原型 | 规格 |
   | --- | --- | --- |
   | 卡片 | `rounded-[24px] border p-4 space-y-4` + `controlCardBg` | 24px 圆角、16px 内边距、16px 间距 |
   | 多选一 pill | `VisualizerPresetGroup` / `getAccentOptionStyle` | `px-3 py-2 rounded-full text-sm border`；**选中 = `--text-accent` 描边 + `inset 0 0 0 1px` 内阴影 + accent 淡底（14%）**；未选中 = secondary 18% 描边 + 主题背景 28% 底；文字一律 `--text-primary` |
   | 「默认」按钮 | `ResetSectionButton` | 卡片**头部右侧**（标题+描述在左，`justify-between`）；`inline-flex rounded-full border px-2.5 py-1.5 text-xs` + 12px 回环图标 + 文案「默认」（宿主 i18n 的 `ui.default`） |
   | 滑块 | `rangeInputClass` | 6px 高圆角轨迹、14px 圆 thumb、`accent-color` 走主题色 |

   判断依据只有一条：**并排看不出哪个是模组插的**。配色差异最常见的原因是用了
   `--text-primary` 当强调色——宿主的选中态用的是 accent。
6. **面板是单例 + 引用计数。** `mount` 会在播放页、设置预览等多处各跑一次，而设置卡片只有一张；
   第二个实例必须共用第一个的节点，否则同一批旋钮出现两份、改一份另一份不动。
7. **旋钮表按「用户要调什么」分组，并且分组这一层要看得见。** 巨幕的 `FIELD_GROUPS`
   分五组（内容与概率 / 歌词处理 / 文字样式 / 跑马灯带 / 斜切丝带），每组渲染成一块**小节**：
   标题走 `--text-accent`（与内置模式莫奈面板同一套分层）、组间一条细分隔线。
   命名照用户的说法（「带速」「字号」「字距」「带高」），说明里写「什么时候会出屏」
   「哪一档是兜底」这类**后果**，不写实现。顺序按「从整体到局部」：先决定轮换出什么，
   再决定字怎么处理、长什么样，最后才是叠加项。
8. **备注是纯文本，而且只写一行。** 备注走 `textContent` 写进 DOM，`**加粗**` 会原样显示成
   两个星号——那是给 Markdown 文档用的写法，不是给界面用的。长度上限也硬性（中文 64 字、
   英文 240 字符）：一屏二十多个旋钮，每条三行以上就把面板读成文档了。
   `test/unit/mod-system/cineramaTextStyle.test.ts` 的 `writes knob hints as plain one-liners`
   锁这两条——写回 Markdown 或写回一段，测试会直接红。

所有旋钮来源都要**每帧读、不在 mount 时缓存**；导出窗口/旧宿主下 getter 可能缺席，必须能按缺省工作。

## 5. 沟通节奏约定

每轮回复固定包含下面几段，能显著减少「你到底做没做」的追问：

1. **已落地**（带实测数据：分布、节点数、构建结果）——不要写「应该可以」。
2. **需要你确认的**（带**判据**，例如「看面板版本号是不是 0.4.0」「日志有没有 command: …」）——
   环境相关的事不要猜结论，给出可执行的排查顺序。
3. **已知取舍/未实现**（写进 README，别只写在回复里）。
4. **改了哪些文件、边界在哪**：碰到宿主（`src/`、`electron/`）要单独点出来并说明理由——
   巨幕这个 PR 就被要求「收窄到只改 `mods/`」，于是宿主侧的注册表字段方案整个回退，
   改成在模组侧闭环（不声明 `settings` 让宿主自然不渲染）。
5. **默认值与假设**要写出来（例如「默认 marquee=auto」）。
   用户没说的默认值就是假设，写明了他才能一句话改掉，不用再走一轮「你为什么这么定」。

另外：反例与约束要**沉淀到文档**（README 的「三条轴」章节），否则下一轮又会以「返工」的形式出现。

### 5.1 改动的边界：优先在模组侧闭环

模组是**自带资产**，宿主对新模组只有一个承诺（那个空锚点）。所以碰到「宿主渲染了一份、
模组也渲染了一份」这类冲突时，先找**不用改宿主**的解法：

| 想要的效果 | 改宿主的写法 | 模组侧闭环的写法（优先） |
| --- | --- | --- |
| 宿主不要再渲染模组设置的另一份 | 给 manifest 加字段 `settingsPanel: "mod"`，注册表判断跳过 | **不声明** `visualizers[].settings`——宿主 `createModVisualizerSettingsPanel` 直接返回 undefined |
| 面板值要传达到渲染层 | 给宿主加一条模组存储通道 | 模组内共享单例（`cineramaSettings.mjs`），渲染层每帧读同一个对象 |
| 面板要跟主题走 | 宿主把 theme 传进 mount props | 读宿主已有的 CSS 变量 + `color-mix()` |

判断标准：**宿主改动要能被所有模组复用**，否则它只是把这一个模组的私事塞进了公共层，
之后每个模组都想塞一次。真需要宿主能力时（新协议、新契约），才值得动 `src/`。
