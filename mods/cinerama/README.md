# Cinerama 巨幕

舞台 LED 大屏风格的歌词动画**模组**（mod visualizer 贡献，apiVersion 1）。与内置模式不同：它不进
`src/components/visualizer/`，而是以模组形式经 `folia-mod://` 在渲染端动态加载——纯 DOM 实现，
无 Pixi、无 React、无外部纹理，逐帧只驱动一个 text host。模组加载与信任模型见 `mods/README.md`，
本文只写巨幕自己的东西。

## 代码入口

- manifest / 主进程入口：`mod.json`、`index.cjs`（主进程只在激活时打一行版本日志，读 `api.manifest.version`）
- 渲染端入口（`mount(element, props)` 契约）：`visualizer.mjs`
- 确定性随机：`cineramaRandom.mjs`（对应 sonnet 的 `sonnetRandom`：FNV-1a hash + 相邻不重复抽取，
  同一首歌永远抽到同一套组合，seek 与重建都不洗牌）
- 切分层：`cineramaSplit.mjs`；排版层：`cineramaLayout.mjs`；转场层：`cineramaTransition.mjs`
- 时序：`cineramaAnimation.mjs`（**只有行相位与逐段进度，没有形态**——形态全在转场层）
- 视觉处理层：`cineramaTreatment.mjs`（纯数据，样式抽取 + 叠加元素/特效的参数解算 + `CINERAMA_TUNING` 选项）
- 渲染层：`cineramaRender.mjs`（**唯一碰 DOM 的模块**，样式层 + 叠加层的构建与层内逐帧驱动）
- 实时旋钮：`cineramaOptions.mjs`（倍率 → 实际参数的解析，缺省恒等）
- 编译：`cineramaProgram.mjs`（逐行 plan，seed = `歌名|歌手`）
- 舞台屏体（静态外观层）：`cineramaStage.mjs`

## 编译期：plan

`cineramaProgram.mjs` 的 `compileCineramaProgram` 给**每一行歌词**产出一份 plan：四条轴——
切分（`whole/word/clause/grapheme/half`）、排版（`center-stage/upper-third/lower-third/left-band/right-band/letterbox-wide`）、
转场（`dissolve/fast-blur/press-glitch/pull-back/wipe-out` 五档已实现，**当前只启用 `dissolve`**，见下节；
它同时管**怎么进**与**怎么退**——原先那条「怎么进」的动画轴已移除，见下节），
**样式**（`hero-type/small-type/ribbon-collage`，
即大字报／小字报／斜切丝带）——各自按行种子独立抽取，且**相邻行不重复同一种**。
排版轴**按分组权重抽**（`layoutWeights`：偏置落点一组、宽银幕字幕条一组，居中是兜底）——
等权时五种偏置落点合起来占 5/6，居中的那一档反而成了少数。
跑马灯带**不在编译期抽**：它是叠加项，档位来自面板，形态由解算层按行种子决定
（同样是 seek 稳定的）。`title`（歌曲标题）只被跑马灯带读，用于「带上跑标题」那一档。
行窗口取 `renderHints.renderEndTime`（视觉尾巴），
但被钳到下一行 startTime，绝不越界。切分结果是带时间窗的 `units` 数组，随 plan 一起编译并**进 DOM**：
渲染层按 unit 建 span，逐 unit 算出 0..1 的出现进度（`resolveCineramaUnitProgress`），所以一句歌词是
一道扫过去并依次收住的波，而不是整块出现。

策略层都是纯数据：split 输出 units、layout 输出 flex/字号/字距表、
transition 输出统一的 `{opacity, x, y, scale, blur, clip}` 包络帧（enter/hold/exit 三相，
时长按行窗口占比钳制）、样式输出本组语汇的几何参数（叠加的带另由 `resolveCineramaMarquee` 给）。
只有 `cineramaRender.mjs` 碰 DOM，且每个 builder 只管自己那层怎么动；
行级包络由 `visualizer.mjs` 打在每层自己的根节点上，两边不重叠写同一批属性。没有段落/shot 层——
大屏一次只放一行，还没有需要分组的东西。

## 两条轴：样式 / 叠加元素（参考实录归纳，已落地）

对照 2026MIXUP 现场大屏的两帧实录归纳出**三种排版本体**，外加**一个可叠加的东西**，全部由
`cineramaTreatment.mjs` 解算参数、`cineramaRender.mjs` 绘制。两条轴正交，所以未来加第三条轴
（新的叠加元素）不用改样式表：

| 轴 | 取值 | 性质 |
| --- | --- | --- |
| 样式 `heroWeight` / `smallWeight` / `ribbonWeight` | 各 0~1 | 排版本体，**三个概率权重**：每句按三者之比抽一个（不是多选一，也没有「自动」这一档） |
| 排版落点 `layoutEarlyWeight` / `layoutLetterboxWeight` | 各 0~1 | 落点的**分组权重**（居中是兜底，不进旋钮）：偏置落点一组（上/下三分之一、左右两栏）、宽银幕字幕条一组 |
| 跑马灯带 `marquee` | 关 / 自动 / 双带 / 四边 | 叠加**元素**，可叠在大字报、小字报上；**不与斜切丝带组合** |

**已移除：印前故障（套版错位）**。它曾是第三条轴（关 / 自动 / 开 + 强度 / 频率），做法是把
样式层**再建两遍**当 `screen` 混合的错位副本（accent / secondary 各一片），偏移量按 `stepHz`
阶梯抖动、落位后收敛到 35%。移除的原因是**效果不佳**：上屏读出来是「字糊了一层、边缘发毛」
而不是「印刷没对准」，而且副本要跟着正片一起 update、一起 dispose，节点数与每帧开销直接翻三倍。
转场里的 `press-glitch`（套版闪断）**不在启用池里**（见下节），它本身不产生这个观感，因此保留实现。

样式的三个权重**只看相互比例**（0.4 / 0.2 / 0.4 与 2 / 1 / 2 是同一套分布），拖动即时生效：
某一项拖到 0 就是整首不再出现该样式，三项全 0 时回落到小字报——
它是唯一**无条件支持**的样式。抽取仍在**编译期**做（要「相邻不重复」，那是一条逐行串下来的
链），所以权重变化时渲染层按 `cineramaStyleWeightSignature` 重编 program 并重建当前层，不等下一行。

**每个样式都有启用条件**（`CINERAMA_STYLE_SUPPORT`），不满足的不进随机池——大字报无字素上限（长句按词切块）、
空行不会被小字报顶掉但**一条带都不画**（`ribbonTextsOf` 返回空数组 → 渲染层整层跳过，屏上就是干净的屏体），
这些限制本身就是效果的一部分：

1. **大字报（hero type）**——整行按 **词** 切成若干块逐块闪现，**一次出的词始终在屏幕内**。
   （每块的入场时刻跟着**它自己那几个词**，不是把歌词窗口按块数均分——见「逐字时序（跟唱，不等分）」。）
   分词口径与凝彩同源（`segmentCineramaWords` = `Intl.Segmenter(word)`，用户存过的
   `line.wordSegments` 优先，见 `src/utils/lyrics/wordSegmentation.ts`），空白折进前一个词、
   标点粘在前一个词上——固定字数是行不通的，「摊开」会被切成「摊」「开」，既破了词又变了味。
   并块（`buildHeroChunks`）也不是「一次出几个词」的定值，而是一个**概率因数**
   `heroChunkChance`：从 1 个词起，每收进一个词就按这个概率再并下一个（掷点按 seed + 块序号，
   seek 与重建不洗牌）——与凝彩的 shot 按种子抽 2~4 词收块同一条思路；定长并块会让每块一样长，
   一句歌词读下来是打点而不是说话。概率只决定常态，**硬约束仍是「装不装得下」**：并进来的
   字号会跌破阈值就不并；单个词本身就装不下时（超长英文词）按字硬切；块数封顶 `maxChunks`（5）
   后按「合并最窄的相邻两块」回收——此时允许字号掉一档，但不允许掉到 `minFontVh` 以下
   （被它抬回去的字号会真的出屏，出屏比字小严重得多）。字号取**所有块里最苛刻的那一份**
   （`heroFontVhForChunk`：竖向 ≤`maxFontVh`（51.2vh），横向 ≤`usableWidthVw`（73.6vw）÷当量宽度，
   取小者），所以块间不跳字号，
   且**默认倍率下**、任何画布比例下一次出的词都不出屏。当量宽度按字种近似（CJK/全角 1.0em、
   大写与数字 0.62、小写 0.55、窄符号 0.4）——解算层跑在浏览器之外，量不到真实字宽，只能宁可估宽。
   **面板那条「文字样式 · 字号」不乘在切分阈值上。** 历史旋钮 `heroScale` 走的正是那条路
   （要求每块至少这么大 → 装不下就多切一块），它已从面板撤下、解析层恒为 1，所以阈值恒等于
   `fitFontVh`。现在整条链**只有一个乘法位置**：渲染层写 CSS 的那一处，`> 1` 会顶破安全区
   ——这是刻意的取舍，见「文字样式」一节。

   **整档字号按 0.8 重新标定过**（原默认太大）：`maxFontVh` / `usableWidthVw` / `minFontVh` /
   `fitFontVh` 四个数**一起**同比缩放（64→51.2 ｜ 92→73.6 ｜ 14→11.2 ｜ 32→25.6），每块的安全
   字号因此严格变成原来的 0.8 倍，而「这一块装不装得下」的不等式两边同时缩小、**解集不变**：
   切成几块、哪几个词并一块、闪现几次全部照旧，只有字整体小两成。四样必须一起动——
   漏掉 `fitFontVh` 就会切得更碎，漏掉 `usableWidthVw` 则长句不再按宽度收字号。好处是
   「面板显示的倍率 = 画面用的字号」这条语义没变（`min` 与 `clamp` 在这种缩放下半齐次），
   代价是原来的默认观感要往上拖到约 **1.25** 才拿得回来。
   **块级动效**是这一档的全部内容（都是 `(seed, 块序号)` 抽、seek / 重建一致）：
   1. **字号微差**：相邻两块在 `HERO_CHUNK_SCALE_POOL` 里各抽一个（±5%）、相邻不重复。上限是
      **每块自己的安全字号**（横向 73.6vw 与竖向 51.2vh 取小），所以往大走的那块也不会出屏、不会折行；
      宽度接近的块可能都撞在这个上限上，这是有意的上限而不是 bug。
   2. **蒙版填色**（概率按**字数**拟合，见下面的表）：**三层同字**，自下而上——
      **辉光层**（透明字身 + 同色 `text-shadow`）+ **描边层**（`-webkit-text-stroke`，不发光）+
      **实色层**（实色、**不带影子**）。后两层被一对**互补**的硬边蒙版 `clip-path: inset()` 扫过、
      共用**同一个行程** `u`（＝这一块窗口的进度，也就是这一块的歌词时间），所以字是**跟着唱**填满的：
      没扫到的部分只剩描边，扫过的部分只剩实色，`u = 1` 时描边层整块裁掉、回到原来的观感。
      方向按块抽（水平 左 → 右 / 竖直 上 → 下，相邻不重复）。蒙版量的是**字身**不是整屏——
      各层的盒子用静态 `left/top:50% + translate(-50%,-50%)` 收紧到字上（见 `buildHero` 的
      `layerStyle`），否则字只占屏宽中间一段，两头会有大半程空扫。描边宽度是常量
      （`outlineWidthEm = 0.014`，跟着字号走的 em 比例）；每帧两次 `clipPath` 写（last-value 缓存会跳掉
      没变的帧）。
      - **辉光为什么要单独一层**：影子会被蒙版一起裁断——填过的地方有光、没填的地方没光，
        交界处出现一道硬边（"辉光被填色裁了"）。所以影子挪到一层**透明字身、永不参与蒙版**的层上
        （`color:transparent` 只挡字身，`text-shadow` 照画）；实色层因此卸掉自己的影子，
        两层叠出来的观感与"实色层自带辉光"完全一样。
      - **不填色的块只有一层**（实色 + 辉光，与不带填色的常规观感一致）：没有蒙版就没有裁断问题，不必拆层，
        一个节点都不多。填色的块多两个文字节点（辉光 + 描边）。
   3. **持续运动**（**只有没填色的块**按权重从 `HERO_MOTION_POOL` 抽）：推近（持续放大
      0.93 → **1.5** + 横向收）、拉远（持续缩小 **1.5** → 0.93 + 横向收）、横移、纵移、
      **摊开**（**一边放大 1 → 1.3、一边把字距从 0 加到 0.15em**），
      以及权重最大的 still（**完全不运动、不缩放**——它是「实色落定、不动也不填」那一档）。
      权重是 **2 : 2 : 2 : 1 : 2 : 4（和 13）**，与填色上限配平（见下面的概率表）。
      **竖直运动只留"纵移"那一档（1/13）**：放大与缩小原本各带 1.2% 的纵向位移，去掉了——大屏上
      横向漂移读起来是"镜头平移"，竖向却很容易读成「字在上下抖」（尤其和上方的跑马灯带一起看）。
      行程**线性**（「持续」要匀速，缓动就成了"落定"），位移从 `xFrom/yFrom` **收到正中**
      （最后一块会长时间挂着，歪着停住很扎眼），幅度按窗口长度归一到
      `CINERAMA_TUNING.hero.motionRefSec`（短闪没时间持续，走少一点）。
      入场那一下仍是原来的 `scale(0.92 → 1)`，两者相乘：一个管"落下"，一个管"挂住时还在动"。
      - **「摊开」的两个终点怎么定的**：峰值 1.3 照需求；字距 `0.15em/字` 是按「不比现有最坏情形
        更糟」反推的——`letter-spacing` 加在**每个字之后**（含末字），一块的宽度增量是 `字数 × 字距`，
        而 CJK 满角本就 1.0em/字（相对增量 ≈ 字距本身），所以横向最坏情形是
        `1.3 × (1 + 0.15) ≈ 1.495`，刚好压在「推近」那档 1.5 的预算里。
        它**不带位移**：字距已经在把字往外推，再加平移就没有"停在正中"这个锚点了。
      - **`margin-right` 补偿**：`letter-spacing` 加在末字之后，居中排时字身会整体左偏半个字距——
        不补的话这一档会一边摊开一边往左挪。渲染层给一个负的 `margin-right`（＝当前字距）
        把内容框加宽同样的量，字就回到正中。**只有这一档逐帧写字距**，其余的块一个样式都不多写。

   **填色与运动不重叠**：会移动/缩放的块**不填色**，做填色的块**原地不动**（取恒等运动）。
   两套动作叠在同一块上会互相打架——字一边被放大一边被一道边界扫过，读起来既不像"填"
   也不像"推近"。所以每块只做一件事，填色与运动**此消彼长**。

   **各动效的触发概率**（一块 = 一次闪现里的一个块）：

   | 动效 | 触发条件 | 概率 |
   | --- | --- | --- |
   | 入场（缩放 0.92 → 1 + 淡入） | 每块 | 100% |
   | 字号微差 ±5% | 每块 | 100%（相邻不重复） |
   | 斜体 | 每块 | 35%（`italicChance`；只有纯拉丁块看得出来） |
   | **蒙版填色** | 每块，**按字数**拟合 | 1 字 **0%**｜2 字 **2.1%**｜3 字 **6.7%**｜4 字 **11.3%**｜≥5 字 **13.3%**（上限 `cap`） |
   | 填色方向 横 / 竖 | 只对填色的块 | 各 50%（相邻不重复） |
   | 推近（放大到 1.5） | 不填色的块 | (1 − 填色概率) × 2/13 → 到上限时 **13.3%** |
   | 拉远（缩小到 0.93） | 不填色的块 | (1 − 填色概率) × 2/13 → 到上限时 **13.3%** |
   | 横移 | 不填色的块 | (1 − 填色概率) × 2/13 → 到上限时 **13.3%** |
   | **摊开**（放大到 1.3 + 字距加到 0.15em） | 不填色的块 | (1 − 填色概率) × 2/13 → 到上限时 **13.3%** |
   | 纵移 | 不填色的块 | (1 − 填色概率) × 1/13 → 到上限时 **6.7%** |
   | 静置（不动也不填） | 不填色的块 | (1 − 填色概率) × 4/13 → 到上限时 **26.7%** |

   **七项是配平好的**（口径：填色上限 / 放大 / 缩小 / 横移 / 摊开 **五者相等**，纵移是它的**一半**、
   静置约是它的**二倍**）：七项和为 1 → 每份 = 1/7.5 = **2/15 ≈ 13.3%**。`cap` 与运动池权重是
   同一个式子的两个未知数（`cap = (1 − cap) × 2/13` → `cap = 2/15`），改一个必须连着改另一个
   （多加一档 weighted 2 就把 `cap` 从 2/13 推到 2/15）。
   实测 600 个「到上限的长块」（≥5 字）：填色 14.8%｜放大 16.5%｜缩小 13.2%｜横移 11.3%｜
   摊开 13.2%｜纵移 7.3%｜静置 23.7%（样本噪声内与目标 13.3×5 / 6.7 / 26.7 一致）。

   填色的曲线是 `cap × smoothstep(t)`、`t = (字数 − 1) / (5 − 1)`，锚点在 `TUNING.hero.fillChance`
   （`from / to / cap`）：**1 个字不用**（一个字的"扫描"没有过程可言，只会闪一下，读起来像故障）、
   **2 个字小概率**、**5 个字及以上到上限**。两个后果值得知道：

   - **一个字的块（"的""了""是"这类虚词）永不填色**，短块也基本不填——填色因此集中在"有份量"的
     长块上，而且**只在长块上**才和其余六项配平。按 12 句中性 CJK 歌词（10~13 字/行，16:9、
     默认并块概率）的块长分布 `1字×9 / 2字×13 / 3字×7 / 4字×5 / 5字×8` 算，**整行平均触发率 ≈ 5.6%**
     （原先一律 5/10 的口径是 50%）：填色因此从"每两块来一次"变成**偶尔一次的点缀**。
     想让填色更密，把 `cap` 提上去（同时按上面的式子改池子权重），或把 `to` 从 5 收到 4。
   - **填色与运动此消彼长**：填色降下来，不填色的块变多，运动（推近/横移/摊开/…）的总量就上去。
     现在静置（4/15 ≈ 26.7%）是最高频的单项，其余六档接近均分。

   所有数都在常量里，不进面板。

   **整档 / 整行层面的概率**（与上面的块级概率**相乘**，不是相加）：

   | 层面 | 动效 | 概率 |
   | --- | --- | --- |
   | 样式 | 大字报（本档） | `heroWeight / 三项之和`，缺省 **40%**（面板可调；只在本行支持时才进池） |
   | 样式 | 小字报 | `smallWeight / 三项之和`，缺省 **20%**（兜底，任何行都支持） |
   | 样式 | 斜切丝带 | `ribbonWeight / 三项之和`，缺省 **40%** |
   | 并块 | 每收一个词后再并下一个 | **55%**（`heroChunkChance`，面板可调；前提是并进来还装得下） |
   | 跑马灯带上的文本 | 歌名 | **25%** 系数（`marqueeTitleChance`；没命中才在原文 / 译文里按 seed 抽） |
   ⚠ **已知取舍：放大到 1.5 会压到跑马灯带上**。满档 51.2vh 的字 × 1.5 = 76.8vh 的字框，而带子画在正片
   **之上**、占上下各 15%，所以放大过程中字的上下两沿会钻到带子底下被盖住；push 这一档结束停在
   1.5，最后一块（会长时间挂着）就一直是这个状态。要「到 1.5 又不压带」只有两条路：① 基准字号
   按最大倍率预留（`maxFontVh` ÷ 1.5，静止的块也一起变小）；② 改成"胀一下再回来"（峰值 1.5、
   落定回 1）。当前是按「`scaleTo` 加大到 1.5」的字面实现的。
   （候选动效——色差收束 / 块间交叉 / 扫光 / 软边填色——都单独评过，**一个都没引入**：
    色差与块间交叉会和"字要读得清"打架，扫光要多一份文字节点，软边填色的羽化掩膜每帧要重新
    光栅化（成本比硬边高一档）、观感也没更好。落进这一档的只有**硬边 + `clip-path`** 的蒙版填色。）
   实心填充、带 ±2° 旋转、**斜体只给纯拉丁块**——CJK / 全角 / 假名没有真正的斜体字面，
   浏览器会做合成倾斜（整字被斜切），一个方正的大字报单字被这么斜一下读起来是渲染出错
   而不是设计（「大字报特效文字有奇怪的偏转」有一半来自它）。长度无上限——再长的行也按词切块逐块闪现，
   装不下的长句自然切更多短块（块数封顶 `maxChunks` 防碎成打点），不会回退到小字报。

   屏角原本还挂译文与歌名的小号元数据标签（实录里左上 "fashion promo" 那类），**已去掉**：
   跑马灯带现在四条边都占着，标签只能和带上的滚动字挤在一起，读起来像一句错位的歌词
   （「左上角有错行的文字」说的就是它）。
2. **小字报（small type）**——**居中、保持行距**，按排版轴给的字号与字距，units 作为 inline span
   逐段依次落位。它是**兜底样式**：任何行都能排成小字报。
   带可以叠在它上面。

   字号 = **排版轴 `fontScale` × `CINERAMA_TUNING.smallType.baseVh`**，在**解算层**算完
   （`resolveCineramaStyle` 的 `fontVh`）再交给渲染层；用户那一侧只剩「文字样式 · 字号」
   这一条统一倍率，乘法只发生在**渲染层写 CSS 的那一处**——两处各乘一遍就会出现
   「面板显示的倍率」和「画面用的字号」对不上（大字报的 `heroFontVh`
   就是这条规矩）。本体默认 **`14vh`**（随屏面铺满整体放大过一次）：它在 2.4:1 的墙上仍然偏小，
   而小字报是兜底样式、出镜率不低，读起来像「没排过版的字幕」。`maxFontVh`（26）只防跑飞的倍率，
   真正的边界是排版轴的 `padY` 与容器的 `overflow:hidden`：**调过头会被屏沿裁掉，而不是自动缩回去**
   ——小字报没有「装不下就多切一块」那条路，那是大字报的机制。

   折行发生在**文本块**里，整块再按排版轴垂直落位（上 / 中 / 下）。以前外层是
   `flex-wrap:wrap`、units 直接当 flex item：容器是 `inset:0`（整屏高）而 `align-content`
   默认 `stretch`，于是几行文字被**均分到整个屏高**上，行距被拉开成一大片——
   「小字报不是分散对齐，而是居中保持行距」说的就是它。现在行距完全由 `line-height` 决定。

### 转场（transition）——行与行之间那段交接

转场是编译期的一轴，它描述的不是「这一行长什么样」，而是**这一行与下一行之间那段交接**。
它同时管**怎么进**与**怎么退**：紧邻时退场与下一行的入场在同一段窗口里**交叠**；
不紧邻时没有交叉对象，同一对 enter / exit 帧由渲染层按行窗口的相位直接取用。
（原先「怎么进」另有一条动画轴 `fade/slide-up/wipe/zoom-settle/flicker`，**已移除**，理由见本节末尾。）

参照 sonnet 的 shot 转场（`sonnetTransitions.ts`）归纳的三条，也是这里的设计前提：

1. **转场是边界上一段独立的短窗口**，不是「行自己的包络再跑一遍」。窗口长度按
   「这一行起始 → 下一行起始」的间距给（`× 0.22`），钳在 0.14~0.28s——sonnet 是
   0.14~0.24，巨幕字更大、屏更满，上限放到 0.28。短句因此不会整句都在转场。
2. **退出方与进入方同时存在**（monet 的叠层交叉、claddagh 的 exit/enter 交叠是同一类做法）。
   改成两层之前，每层都在自己的窗口内淡到 0 才换层：行与行之间必然出现一帧**两层都是 0**，
   大屏上读出来是「每次换行都眨一下」。现在旧层留在屏上当退出方、冻结在最后一帧，
   新层走它自己的 enter 包络进来，中段两条叠到 ~1.1（实测），不再有空帧。
3. **形态按种子抽、且不与上一次重复**（`chooseCineramaWithoutRepeat`），与切分 / 排版 /
   样式同一套口径，seek 与重建都不洗牌。抽的池子是 `CINERAMA_TRANSITION_POOL`
   ——**当前只有 `dissolve` 一档**，所以现在每一处交接都是同一种退法：先把最通用、
   也最像「LED 屏内容换代」的溶解跑稳，其余四档实现了但不参与抽取。

五档形态（帧形状恒为 `{opacity, x, y, scale, blur, clip}`，渲染层不需要分叉）：

| 形态 | 效果 | 状态 |
| --- | --- | --- |
| `dissolve` | 交叉溶解：不透明度走 smoothstep 到 0，整屏轻微收敛（scale 1 → 0.97） | **启用** |
| `fast-blur` | 失焦退场：先虚掉再消失（sonnet 的 fast-blur 同一条思路） | 停用·已实现 |
| `press-glitch` | 套版闪断：阶梯抖动 + 后段硬切，沿用印前故障的语汇 | 停用·已实现 |
| `pull-back` | 推拉退场：整屏往后退一点再淡掉（sonnet 的 camera-pull） | 停用·已实现 |
| `wipe-out` | 擦除退场：从下沿往上抹掉，像整屏换帧 | 停用·已实现 |

**「停用」不是删掉**：实现留在 `resolveCineramaTransitionFrame` 里，只是不进抽取池，
把它加回 `CINERAMA_TRANSITION_POOL` 即刻恢复。`CINERAMA_TRANSITION_KINDS` 始终是五档，
测试也是按「已实现」的那份遍历的，所以停用的档位不会被测试漏掉；
恢复多档后「相邻两句不许同一种退法」那条断言会自动重新生效。

三条容易踩的坑，实现里已经处理：

- **退出方冻结，不继续 `update`**。大字报的块是按行窗口逐块闪现的，越界之后所有块的
  opacity 都是 0——继续 update 会让退出方在交叉那一段里变成空白，交叉就成了
  「先空一下再淡入」，正是要去掉的那种眨眼。
  **丝带是例外**（`cineramaOutgoingKeepsMoving`）：它整行都在屏上（没有逐块闪现那一套），
  而且**它是有运动的**（文字匀速滚动 + 上下漂移）。冻结那 0.14~0.28s 的交叉读出来就是
  「丝带卡住了」——所以丝带的退出方照常 `update`，只是根节点照常走溶解包络。
- **末段一律收到 0**。fast-blur 末段还留 18% 不透明度、pull-back 留 28%，而退出方是在
  窗口末尾被**拆掉**的——那一刻还亮着，读出来是「啪」地一下消失。所以所有形态在窗口
  最后 15% 统一乘一道收尾。
- **入场与退场共用同一套形态**（`resolveCineramaTransitionEnterFrame` / `ExitFrame`）。
  入场之所以不能另设一条形态轴：早先那条动画轴里的 `wipe` 是 `opacity` **恒为 1** +
  `clip-path` 自左向右揭开——它不淡入，边界是一条竖直硬边，交叉的时候扫过还没退干净的
  旧层，屏上同时是新旧两份内容、中间一条边界，读出来就是「屏幕横向刷新了一下／像扫描线
  在两个画面之间切」；因为形态是按行抽的，症状还是**时有时无**的。现在入场恒走转场这条
  （当前只启用 dissolve，是一条纯 opacity 渐变、`clip` 恒为 `null`），硬边不可能再出现。

**已移除：动画轴（`fade / slide-up / wipe / zoom-settle / flicker`）**。它只在**没有交叉
对象**时才生效——紧邻时被转场的 dissolve 顶掉，而密集段落的绝大多数行都是紧邻的，
剩下首行与几处间奏后各露一次，五档里每一档整首歌的出现率是个位数百分比，且**零测试覆盖**。
移除后形态只剩转场这一套：要多样性就往 `CINERAMA_TRANSITION_POOL` 里加档（那时进与退会
一起变，不会再出现「一会儿硬边、一会儿溶解」的混搭）。`cineramaAnimation.mjs` 现在只剩
行相位与逐段进度。

**不紧邻就不交叉**：下一行起始离这一行窗口结束超过 0.6s 算有空档（间奏），那时没有交叉
对象，这一行按转场的 exit 帧自己淡出（`resolveCineramaLinePhase` 传 `exit: 0` 即
「退场交给转场窗口」，不紧邻时才是这一行自己那一段 exit 相）。
换主题、改结构旋钮也不做交叉——旧层是旧配色 / 旧档位，留着退场
只会拖出一帧错色的残影。渲染层因此是**两个槽位**（当前行 + 正在退场的上一行），
包络写在各层自己的**内容层**（`buildCineramaLayer` 返回的 `envelope`）上，
不再打在共享的 `stage.textHost` 上。

**两层拆成「内容」与「屏级家具」**：层树是 `root → [envelope（内容）, bands（跑马灯带）]`。
跑马灯带占的是屏沿那一圈，是这块屏的边框、不是这一行的内容：

- **几何在整段转场里恒定**——dissolve 那一帧带 `scale: 1 - away * 0.03`，
  若把带子放进被缩放的那棵子树，两层各缩在不同进度上内沿就会错开
  （「过渡时框的大小变了、内边缘不重叠」），缩放以盒子中心为原点还会把贴着屏沿的那一侧
  向内拉开一截（双带最左侧与屏左沿出现间隙）。所以带子留在 `envelope` **之外**，
  转场绝不写它的 `transform`。
- **但带的字必须换手**——带整段都在屏上、字又比内容大得多，两层同时在屏上时
  两份带上的字叠在同一圈上会互相穿插，读出来是一团花。所以带子有自己的一套存在度
  （`cineramaTransition` 的 `resolveCineramaBandExitPresence` / `EnterPresence`）：
  **退场方前半场淡出、进入方后半场淡入**，两个半场严格互斥，
  任何一帧屏上都只有一条带；换字恰好落在窗口正中（内容也正交叉到各自 50%，
  最不显眼的位置）。`visualizer.mjs` 对 `layer.bands` **只写 `opacity`**，其余属性一概不碰。

下面是**叠加层**，不是样式：它建在样式层之上（带在最上）。第三条轴「印前故障（套版错位）」
已移除，理由见上一节。

两种带型共用**两条正交的轴**（面板的「带身填色」与「边线」）：一条管带子那块区域**着不着色**，
一条管区域的**边沿怎么画**。两轴分开之后「实线 + 底色」这类组合才表达得出来；
存量旧值由 `cineramaOptions` 的迁移表翻成一组新值再解析，
观感与旧安装保持一致。每条轴再各挂**色轴**与**边线范围**两个从属旋钮（下面三节）。

**边线**（`marqueeEdge`，默认 `glow`）：

| 档位 | 效果 | 用在什么场合 |
| --- | --- | --- |
| 不画边 `none` | 只画字，沿上什么都不画 | 要字「浮」在屏面上，不要任何框 |
| 实线 `solid` | 一道 1px 实线（缺省辅助色） | 勾出「这是一条带」，但不想抢字的戏 |
| 辉光 `glow`（默认） | **只有光、没有实线**：亮芯 + 两圈扩散 + 一圈溢出，缺省强调色 | 边与字同一个光源（实录里那种被灯打亮的舞台边） |

**填色**（`marqueeFill`，默认 `none`）：

| 档位 | 效果 | 用在什么场合 |
| --- | --- | --- |
| 不填色 `none`（默认） | 区域全透明 | 实录那一档：带子本身就是屏体，靠**边线那道灯**与带上的字读出来 |
| 淡色底 `tint` | 一层带**色相**的极淡底 | 想让带子读成一块独立面板、把字从样式层里托起来 |

边线一律用 `box-shadow`——阴影不占布局、不会把字推离屏沿，「只画边」与「填色 + 画边」的几何
也完全一致。辉光的**扩散半径按带厚取比例**（带高本身是旋钮，6~20% 屏高）：写死 px 的话
细带上光晕糊满整条、粗带上只剩一条硬线。

**辉光档不画 1px 实线**（那是 `solid` 档独占的硬边）：两者互斥，「描边 + 发光」等于把同一件事做两遍。
但边沿仍要**定得住**，靠的是三层里最里面那口**亮芯**——一条贴边的软亮带，不是一条线。

辉光档的三层都是**同心阴影**（偏移恒为 0），都从被画的那条边沿出发：

| 层 | 半径（相对带厚） | 浓度（满档） | 作用 |
| --- | --- | --- | --- |
| 亮芯 `coreRatio` | 0.22 | `coreAlpha` = 100% | **色轴的载体**：贴边、收得最紧，换色就靠它看得出来 |
| 中间层 `midRatio` | 0.5 | `innerAlpha` = 42% | 把亮芯与带内的字接上，中间不留空 |
| 外层 `wideRatio` | 0.5 | `wideAlpha` = 22% | 更宽更淡的那一圈；它越过带沿的那半个尾巴就是「往屏面渗」 |

**三层里最大的半径也必须小于一个带厚**（这里三个都 ≤ 0.5）：同心之后「往屏面渗」由外层
自己越过带沿的那半个高斯尾巴完成，不再需要、也**不允许**再给一个超过带子的半径——
半径超过一个带厚就不再是「一条边」，而是一层漫过半个带子的雾。

「边线范围 = 双侧」时，贴着**屏幕边缘**那条边（外沿）也要画，而它的另一侧是**屏外**——
那一半在画布外，物理上画不出来，所以它那三层只能是「往带里渗」：

| 层 | 半径（相对带厚） | 浓度（满档） | 作用 |
| --- | --- | --- | --- |
| 亮芯 `coreRatio` | 0.22 | `coreAlpha` = 100% | 与内沿**同值**，不因外沿看得见的那半边被裁掉就加浓 |
| 外沿往带里 `outerRatio` | 0.5 | `outerAlpha` = 46% | 补上外沿缺的那层渐层（见下） |
| 外沿往屏内 `midRatio` | 0.5 | `wideAlpha` = 22% | 与内沿同值 |

**外沿必须与内沿层数齐**：少了中间那层，读出来就是「外侧那圈光几乎看不见」——
内沿是「窄亮芯 + 中间层 + 宽层」的连续渐层，外沿只有「亮芯 + 最宽那一层」时中间那一截空着，
屏沿上成了「一根窄亮芯 + 一大片极淡」。外沿没法用「加浓亮芯」把这一截补回来——
加浓只会把屏沿烧成一条白线，所以**补层数，不是补浓度**。`outerAlpha` 比内沿的 42% 略浓一点（46%），
因为屏沿那圈有一半落在屏幕之外被裁掉，视觉分量本来就少。

**半径**乘辉光强度；**浓度**走 `alphaFloor + (1 − alphaFloor) × 强度`（`alphaFloor` = 0.55），
不是直接乘——直接乘的话缺省 0.3 会把亮芯压到 30%、光晕压到 5%，屏上只剩一根**读不出颜色的灰线**。
走这条曲线，缺省档落在 0.68，色轴在缺省档就够浓；
拖到 1 仍是各层满浓度、满扩散，拖到 0 整档一起消失。

**亮芯必须跟带内字号一个量级**（字高 ≈ 带厚 × 0.55）：半径比字号小一个数量级时，
屏上读出的是**一根灰白细线**而不是一道灯。

**没有亮芯时「边线色彩」是换不动的**：色轴只挂在宽光晕那两层上，而带上的字自己带一圈
**同色 `text-shadow`**，换色在屏上读不出来。

### 色轴：填色与边线各一条

面板给填色、边线各一档色（`marqueeFillColor` 默认 `accent`，`marqueeEdgeColor` 默认 `auto`）：

- **填色**：`accent`（底与带上的字同一个光源）或 `secondary`（底与字分成两层）。
- **边线**：`auto` **按档位配**——辉光取 `accent`（字已经在发光，边再换一个色轴就等于把
  「字在带上」说两遍）、实线取 `secondary`（它勾的是范围，字是强调色、范围是辅助色，
  一眼分得开）；也可以强制成 `accent` / `secondary` 覆盖这套搭配。

填色的浓度仍是极淡底（暗底 12% / 亮底 9%）：带子是底纹不是色板，浓了会盖住样式层的字，
而中性灰那版观感只是「蒙了一层灰」，压不住字也没有身份。

**亮色主题下辉光不发光，但仍取色**：浅底上 accent 发光等于没画，层次改成**压进屏面的一道暗槽**
——与丝带那条规则同源（见 `ribbonSkin`：亮主题用投影、暗主题用外发光）。换的是层次的表达方式，
**不是颜色**：槽色由色轴压暗到 `darkMix`（58%）再 alpha 化，读作「一道有色的深边」。
写死 `rgba(0,0,0,α)` 就等于把色轴整条丢掉，浅底上换色毫无反应。彩色那一份过 `color-mix` 让浏览器做 alpha 化——
主题色是任意格式的 CSS 字符串，模组侧做不出可靠的透明化。

### 边线范围：内侧 / 双侧

带子占的那块区域有两条长边：靠**屏幕中心**的那条（内侧）与靠**屏幕边缘**的那条（外侧）。
`marqueeEdgeSides` 默认 `inner`，只画内侧——双带是上下两条各自朝屏心的那条长边，
四边是环上朝屏心的那四条边。改成 `both` 就连贴着屏幕边缘的那条一起画
（四边表现为屏沿上多一圈贴边的光 / 线）。

**外沿的光只有一半，所以它比内沿更容易「看不见」**：内沿的两侧都在屏上（带里 + 屏心），
外沿的另一侧是屏外，`outset` 那一半根本画不出来。所以外沿的三层全走「往带里渗」，
层数必须与内沿齐（少一层就是少一整截渐层），而亮芯浓度与内沿共用同一个值。

**两条短边一律不画**：双带最左 / 最右那两端正好落在屏幕的左沿与右沿上，给它们上边会把
「带子在这里结束」写进画面，而带上的字是循环的、根本没有端点。

这条约束**不能只靠「不写声明」实现**：边线用的是**同心**阴影（`inset 0 0 <半径>` /
`0 0 <半径>`，偏移恒为 0），它以盒子的**四条边**为对称轴——不写短边也照样会从短边渗出来。
所以凡是承载边线的盒子，横向都必须向屏幕外伸出（见下一节「边线节点横向外伸」）。

### 边线节点横向外伸：屏幕左右两侧不许有光

同心阴影既然以四条边为轴，盒子最左 / 最右那两条**短边**就各会渗出一圈光；而边线节点
若写 `left:0; right:0`，那两条短边**正好压在屏幕的左右沿上**，屏上读出来就是
「左右沿各多出一道光」。

**修法是把节点在 x 方向上加长。** `left` / `right` 取同一个负百分比
（`TUNING.marquee.edge.edgeHaloOverscan`，缺省 0.5 = 半个视口宽），两条短边连同它们的光一起
落到屏幕之外；两条**长边**仍在屏内、位置不变，所以内沿那条灯完全不受影响。

两个节点都要外伸，**但理由不同**：

- `haloNode`（内沿，`left:0` 换成 `left:-50%`）：它本来就画在带盒**外面**，直接改横向即可；
- **「屏沿」那一套也要搬到自己的节点上**：画在带盒的 `box-shadow` 上时，带盒的
  两条短边会在屏幕左右沿各渗一圈光。而带盒**自己不能**向屏外撑——它的 `overflow:hidden`
  与文字行盒的 `left:0` 是**循环字带的锚点与滚动几何**的前提，撑出去整条字带会推歪。
  所以另起一个纯装饰节点（几何与带盒同区、同样横向外伸），带盒只剩裁字与填色。

那层屏沿节点必须挂在**带盒之前**：`box-shadow` 画在盒子自己的背景层上、低于它的子内容，
所以它天然压在带上的字**下面**；搬到独立节点后要保住这个层次，挂在带盒之后就会把光
盖到字上面。

### 双带的内沿必须画在**带盒外面**（与四边同构）

内沿这条线**只有双带会画错**，因为两档带型的边线画在完全不同的盒子上：

- **四边**：内沿那半套由 `ringEdgeDeclarations` 拆给两个盒子——`frameFill` 的 `inset`
  （padding box 就是屏心那块）负责「往屏心渗」，另一个 `inset:<带厚>` 的盒子用 `outset`
  负责「往环里渗」。两个盒子各管一侧，光以**内沿那条线本身**为轴；
- **双带**：内沿那半套**不能**画在带盒的 `box-shadow` 上。带盒是 `overflow:hidden`、
  而且**只有带子那么高**——两条长边（屏沿与内沿）相距才一个带厚。于是两个后果叠在一起：
  画在盒内的光被内沿那条线**硬切一刀**（切点恰好是峰值），两层 `inset` 又从**两条边同时**
  往里渗、在带子中间叠加。屏上读出来是「一条从带子中间一路爬到边上、到边上被剪断的亮带」。

**改法**：内沿整套搬到一个**自己的节点**上（`buildMarqueeBands` 的 `haloNode`）：

- 盒子的**内部 = 屏面那一侧**，靠内沿那条边就是它的边界（上带 `top:<带厚>` + 撑到屏底，
  下带 `bottom:<带厚>` + 从屏顶撑起）；另一条边落在屏外，看不见；
- `inset 0 0 <半径>`：画在盒内，**往屏面渗**——对应四边 `frameFill` 的角色；
- `0 0 <半径>`（outset）：越过那条落在内沿上的边，**往带子里渗**——对应四边 `innerHalo` 的角色；
- 它挂在带盒**外面**（兄弟节点、在后），所以不落在 `overflow:hidden` 的作用域里。

「屏沿」那一套（「边线范围 = 双侧」时才画）也搬到**自己的节点**上：屏幕的框钉在屏沿上、
不跟着灯跑，而且离内沿有整整一个带厚，不会与内沿那套在带子中间叠加。它同样横向向屏外
伸出（理由见上一节），并挂在带盒**之前**以保住「光在字下面」这个层次。

改完之后内沿在**整个走带周期里纹丝不动**，峰值落在内沿本身上、两侧连续。

### 边线各层的半径必须**小于一个带厚**

同心之后「偏移 = 半径」那条约束不再需要（偏移恒为 0，不可能落错边），但**半径本身**
还有一条硬上限：超过一个带厚就不再读作「一道边」，而是一层漫过半个带子的雾。
双带的外层（`wideRatio`）因此收进一个带厚以内——「往屏面渗」由它自己越过带沿的那半个
尾巴完成，不需要一个比带子还宽的半径。

三层之间照四边档的分配：亮芯 `coreRatio`（色轴载体，最浓）< 中间层 `midRatio`
/ `outerRatio`（0.5，浓度 `innerAlpha` / `outerAlpha`）< 外层（同样 0.5，浓度 `wideAlpha`，最淡）。

往屏面那一侧**不能**再画一份亮芯：那样屏上读出来是一条过曝的白边，而不是一道灯。

### 字形与边线不许落进同一个纵向区间（双带）

双带的字与边线**挨得很近**：边线那道灯压在带沿上，而带内字形的墨会画到**行盒外面**
（descender、以及部分字体里超出 em 的笔画）。**连缺省档，字形就已经探到带沿之外**，
而 `alignInner` 量的是 `scrollHeight`（按整格取整、不含溢出的墨），那个数看不见这一截；
字号一拖大，带沿整条被字形骑穿。

屏上于是出现两条线：一条是边线那道灯（压在带沿上），另一条是**字形的边**——它逐字复刻
汉字的下缘轮廓，随字距滑动起伏。四边那一档没有这条通路（环上的字在 SVG `textPath` 上，
容器既不裁它、也不让它与边线争同一个纵向区间），所以只有双带会出。

两处一起改：

1. **居中量的是墨，不是行盒**（`measureBandGlyph`，走 `Range.getBoundingClientRect`）。
   按行盒居中时墨会整体偏上、上净空被吃掉；
2. **墨超出净空就把带子撑厚**（`bandMinHeightOf` → `min-height`）。撑的是带高，不是压字号
   （字号是面板上的一轴，改了等于把用户的旋钮掰回去，同屏正文的安全区也要重算），
   也不把边线挪到带外（那道灯压在带沿上正是这一档的设计）。净空按带厚取比例
   （`edgeClearanceRatio` = 8%），带厚一高就跟着高。带子只会变厚、不会变薄；
   撑高那一帧要**按撑之后的带高再居一次中**（否则字号 0.8 那一档上净空 4px / 下 10.9px）。

上下净空之差的实测值 ≤ 0.02px，带高从 6cqh 到 20cqh、字号从 0.3 到 0.8 各档一致。

### 边线那道灯**不许沿带子走**（`marqueeEdgeDrift` 缺省 0）

`edgeDriftSpan` 缺省 **0**：带上的字与边线本来就挤在同一个纵向区间里（见上一节），
让这道灯沿带子走，它就会从字身上穿过去，屏上读成**两处错开的亮区**——稳定的那条是
边线的静态落位，会跑的那条落在字身上。

这一轴**没有被删**：`marqueeEdgeDrift` 仍然缩放振幅，想给的人往右拖就有。
振幅为 0 时连不透明度也不动——否则「一条稳定的边」会读成「一条时亮时暗的边」。

### 辉光是双向的

被画的每条边沿，光晕都**同时往两边渗**：

- **往带子里**：`inset` 那一半画在盒内，或 `outset` 那一半越过盒沿——由盒子怎么摆决定
  （见下面「两侧的划分由盒子的选择决定」）；
- **往屏面上**：`outset` 画出盒外、朝屏幕中心那一侧，或 `inset` 画在「内部就是屏面」的盒子里。

加上贴边的**亮芯**（半径最小、浓度最高，是色轴的载体），暗色主题下每个被画的边沿是**三层**，
带子读作一根**两面发光的灯管**。

**三层全部是同心阴影（偏移恒为 0）**：`inset 0 0 <半径>` 画在盒子内部、以盒子四条边为对称轴，
`0 0 <半径>`（outset）以同一条边为轴两侧都渗。同心是这套代码的**根不变式**：
换成定向阴影（`0 ±<偏移>` 把光压到某一条长边上）就会踩三处坑——偏移小于半径时影子摊到
**两条**长边（屏沿凭空多出一圈）；两层内沿各带一个偏移时落点变成两条**平行**的边（重心错开）；
外层半径给到比带子还宽时光漫过半个带子。零偏移一条同时消掉三处。

两侧的划分由**盒子的选择**决定，不再由符号决定：

- **四边**：`frameFill`（`inset:0` + border = 环）的 `inset` 往**屏心**渗；
  「往环里」那一半另起一个 `inset:<带厚>` 的盒子（`innerHalo`），它的 border box 正好是内沿
  那个圆角矩形，`outset` 阴影这才落在环上；`both` 时再加一个 `inset:0` 的盒子管贴着屏幕
  边缘那一圈（`outerHalo`）；
- **双带**：内沿整套在一个「内部 = 屏面、一条长边落在内沿上」的独立节点上（`haloNode`，
  见上一节）；带盒只管屏沿那一套。

两种带型的盒子都不占布局、不碰带上的字。四边那一档**多两个纯装饰盒子**才画得出来，
双带靠**把带盒腾出来**——两者的结论一样：**内沿这条灯必须由它自己的盒子的边界定义**。

**四边的填色画在 `border-color` 上，不是 `background`**：四边那层是 `inset:0`，border 才是屏沿那一圈
带子，用 `background` 会把**屏心**一起铺满——那一块不是带子的区域。双带的盒子只有带子那么高，
直接画在 `background` 上。

**排版本体让开带子**（`resolveCineramaBandInset`）。带占着屏沿，正文不许压上去；带的厚度到处都写
**屏高的百分比**（`bandPct`），所以上下两条带各占 `bandPct%`，四边的环**四条边都占** `bandPct%`
（左右那两道折成屏宽就是 `bandPct / aspect`）。让开的方式按样式分两种，同一条解算：

- **小字报**整块是按内边距落位的 → 内边距取「排版轴留白」与「让开量」的**大者**（渲染层写三值
  `padding`）；
- **大字报**是居中排的 → 靠**收窄可用框**（`heroTuningWithinBand`）：竖向 `(100 − 上下带厚) ÷ 行高`、
  横向 `73.6vw − 左右带厚`。它同时收窄「能并多大块」的判断与最终字号，所以一次出的词既不
  出屏、也不压到带上。

两个必须踩准的点：

1. **让开量 = 带厚 × (1 + `safeClearanceRatio`) = 带厚 × 1.25**，不是刚好一个带厚。带上的字自己带一圈
   **同色辉光**（`bandSkinOf`），而带内字身只占带厚的五成多——只让开一个带厚的话，正文是「紧贴
   带子内沿」排的，那圈辉光正好糊上去，读起来就是「带子里的字压在正文上」。带子自己的边线光
   也会往屏面渗（`wideRatio` 那一层），同一条余量一起把它让出去。
2. **两个方向各用自家那把尺子**：小字报的竖向内边距写 `cqh`（屏高的百分比）、横向写 `cqw`，
   **不能写 `%`**——CSS 的百分比 padding **四个方向都按包含块的宽度解析**，屏幕越宽「按高度看」的
   竖向留白越大、越窄越小；窄画面上它会小于带厚，正文直接坐进带子里。
   屏体是 size container，`cqh / cqw` 量的就是屏高屏宽，与带子那条 `height:带厚%` 同一把尺子；
   前面另写一行 `vh / vw` 给不支持容器查询的老宿主兜底。
3. **让开量取旋钮本身，不取「这一行抽到的带型」**：`resolveCineramaBandInset` 里的厚度来自
   `resolveCineramaBandPct(options)`，**不是** `marquee.bandPct`。带型在 auto 档是**按句抽**的
   （双带 / 四边交替），让开量若跟着抽中的带型走，同一组旋钮就会在两句之间给出两个不同的安全区
   ——小字报整块按内边距落位、大字报按可用框收字号，于是「换句时带子的形状与位置变了一下」。
   让开量是**屏级的环境量**：带子只要存在，屏沿那一条就一直被占着，而两条带与环的厚度本来就是
   同一个 `bandPct`。`marquee.bandPct` 与让开量**必须同源**，所以两者都从上面那两个解析入口取。

斜切丝带不与带组合，所以那一档 inset 恒为 0（行为与之前完全一致）。

已知残余：**行入场包络**是瞬时的，没算进安全区——入场那一相里整层有 3% 的缩放（dissolve 的
`scale 0.97 → 1`），那几帧里（半透明的、正在动的）字会扫过带子。按它再收一遍会把可用框
压掉一成多，而这一档本来就是「正在入场」的状态，判断下来不值得。

3. **跑马灯带·双带（marquee bands）**——**叠加元素**，只画带：屏体上下各一条循环带（**贴到屏沿**，
   带高 12%），中间那块字由样式层负责（大字报就逐块闪现、小字报就整行），所以「大字报 + 跑马灯」
   是天然的组合。文本内容三选一：当前行整句、上带原文下带译文、或歌曲标题（seed 决定；译文不存在时
   该选项不出池）。

   **下带只在上下两条带跑同一份文本时才 `rotate(180deg)`**（读向相反，凑成「同一条带绕屏一周」的
   错觉）——没有译文、抽到歌名时就是这一档，不需要为下带单独写一套滚动。**文本不同时（上带原文、
   下带译文）绝不翻字**：译文整条倒过来就读不了了。翻转没了以后「对开」这条默认观感得另外保住，
   所以不翻字的下带改成**行程取反**（`marquee.bands[].reverse` → 位移走 `−1 − m`，见渲染层），
   两条带仍是一左一右，只是都正着读。

   **滚动位移取「一份」的百分比**（`translateX(-100/份数 %)`），滚过一份即回绕，接缝不可见。
   这一档的坑全在「铺多长」上，两条缺一不可：

   - **内容要比盒宽多出一份**：位移区间是一份（`[−一份, 0]`，起点贴盒左沿），所以盒右沿之外
     必须还压着至少一份，两端才同时有字，即 `N × 一份 ≥ 盒宽 + 一份`。按「盖住盒宽 × 安全系数」
     算是不够的——两头各多出 10%，而位移一次就是一份宽；短句在宽屏上一份只有屏宽的一成出头，
     旧的 6 份上限远远不够，推出去的那一侧先露白、回绕那一刻字又整块推回来，读起来就是
     「一侧空一截、然后忽然补上」。
   - **按整数份铺、每份都以分隔符收尾**（`repeatBandText`）：`repeatText` 只在份与份**之间**插
     分隔符（N 份只有 N−1 个），元素宽度于是是 `N × 一份 − 一个分隔符`，「滚过一份」不再是
     元素宽度的整数分之一，每绕一圈都差一点，累积起来同样是「滚着滚着错开一截」。
     补上收尾分隔符后宽度按定义就是 `N × 一份`，位移可以写成百分比：**百分比按元素自身宽度
     解析**，浏览器算出来正好是一份，不依赖我们量出来的宽度（量只决定铺几份）。

   内容起点**贴盒左沿**（`position:absolute; left:0`），不用 flex 居中：居中时内容向两侧同时溢出，
   而位移只往一侧推，推出去的那端先露白，另一端多出来的部分永远看不见；溢出量还跟一份的宽度
   没有关系（是 `(盒宽 − 内容宽)/2`），够不够全看书多长。份数按实测宽度算，上限 40 只防跑飞
   （一个字一行在宽屏上也要十几份才够）；尺寸变化与字体就绪会重铺，**重铺只改份数**、
   位移是「一份」的百分比，所以不会跳一下。

   **下带的位移分两种，别写串**（`m` 是上带那条的位移，区间 `[−一份, 0]`）：

   - **翻字那条**（`rotate(180deg)`，上下同一份文本）：映射是 `x → W − x − t`，两个后果都得算进
     位移里——同一个 `t` 在屏上是**反方向**（这正是「上下反向」这条默认观感的来源），而它的
     **左沿会翻到右边去**：`t` 取负值时内容起点被甩进盒内，下带左侧直接空出一份；长句的
     「一份」≈ 整屏，读起来就是「字还没走到屏沿就没了」。所以它走 `m + 1`（区间 `[0, 一份]`）：
     左沿落回盒左沿之外，覆盖条件和上带一样成立，屏上仍是 `m` 的反向。
   - **不翻字那条**（`rotate(0deg)`，上下文本不同）：翻转带来的反向没有了，改让**行程**反向——
     走 `−1 − m`，跑的还是同一份的区间 `[−一份, 0]`，只是方向相反（`m` 从 0 走到 −一份时它从
     −一份 走到 0）。写成 `m + 1` 会把内容推出盒外（`[0, 一份]` 的正向位移对不翻字的带子是露白），
     写成 `m` 则两条带同向走、对开观感丢了。

   两条带的 DOM 一模一样，差别只有 `rotate` 与行程那一步——改位移公式时最容易漏的就是这里。

   **怀疑它没出现时，把设置里「跑马灯带」拨到「双带」即可强制验证**。
4. **跑马灯带·四边（marquee frame）**——不是四条带拼的边框，而是**一条绕屏一周的闭合环形字带**，
   用 SVG `textPath` 实现：一份文本沿**圆角矩形闭合路径**排布（路径按带厚的一半内缩，
   `dominant-baseline: central` 让字心落在环线上），字按路径切线自动转向——上 →、右 ↓、下 ←、
   左 ↑（顺时针绕屏），四角是圆角，字是**转过**拐角的，不在角上断开。

   **为什么用 textPath 而不是逐字摆位**：逐字方案要自己量每个字的步进（canvas `measureText`），
   而量字与渲染字是**两条排版管线**——字体回退、合成字形一旦对不上，量出来的步进就比实际窄，
   字会在环上叠成一团。textPath 让浏览器用**同一套排版**摆字，量长（`getComputedTextLength`）
   与渲染同源，不可能错位；每帧也只写一个 `startOffset`（SVG 自己重排），比逐字 transform
   便宜一个量级。

   **环是严格闭合的**：份数取最接近的整数，把「环长 − 份数 × 一份长度」折成 `letter-spacing`
   （可负＝收紧；有下限 `tightenRatio` 防叠字，过头就少放一份改成放宽）——每份铺开的长度于是
   恰好等于环长/份数，字绕一圈回到原位，任何地方都没有接缝。内容比环**多铺一份**：startOffset
   在 `[-一份, 0)` 之间回绕时，可见窗口两端始终有字；回绕周期按浏览器量出的实际总长折算，
   闭合是精确的。`xml:space="preserve"` 保留歌词里的空格（SVG 默认折叠连续空白）。

   **量长与重排只在三处触发**：能测到尺寸的首帧、`document.fonts.ready`（字体晚到会让步进过期）、
   `ResizeObserver` 报尺寸变化（只翻标记，下一帧 update 里重排，回调里不量尺寸）。层被换掉时
   `dispose()` 断开观察器。

   orbit 只定绕行方向（顺 / 逆时针，seed 决定），字的朝向由路径切线定，不跟着翻——
   翻了就是「逆时针时字全反了」。

   **环上的字色必须自己写 `fill`**：SVG 的 `fill` 是独立于 `color` 的属性（缺省值是 **black**），
  外层 div 上那条 `color`（`bandSkinOf`）**传不进 SVG**。照抄双带的写法就会「配色改了、四边没变」——
  暗色主题下那圈字其实是黑的、等于看不见。所以 `text` 上显式写 `fill:currentColor`，
  让字跟着 `bandSkinOf` 那份颜色走，两档带型共用同一套配色。

  两条形态共用一条硬规则：**带内字号必须用屏体的尺度（`cqh`/`cqw`），不能用 `vh`**。
   带高是屏高的 12%，而 `vh` 是视口高度，两者只在「屏体 = 整个舞台」时才相等；
   用 `vh` 写的时候字号会整条高于带子，被环盒的 `overflow:hidden` 裁掉（「跑马灯带被裁剪」就是它）。
   所以 `cineramaStage` 把屏体做成 size container，带内字号取
   `min(字号 cqh, 字号 cqw)`（窄画面上 cqw 更小，取较小者字才装得进带的厚度），
   上限压在带高的六成，行高锁 1。不支持容器查询的宿主会丢掉 `cqh` 那条声明，
   前面另写了一条 `vh` 兜底。
5. **斜切丝带拼贴（ribbon collage）**——样式之一，3~9 条**实底**胶带（配色跟着主题走，见下面
   「配色与层次」）。错开是解算层保证的：

   - **角度从 ±13°~±54° 的离散档位里不重复抽取**（`RIBBON_ANGLE_POOL` 十档：档位数要够
     `ribbonCount` 的上限 9 用，档位少于条数就会 `index % length` 回绕出两条同角的平行丝带）。
     抽取走 `pickRibbonAngles` 而不是「洗完牌取前 count 个」——**正负交替**（同号连成一排就是
     一叠同向的平行线）＋ **小角限量**（`|角度| < RIBBON_SHALLOW_ANGLE` 的最多占 1/3，
     多了就聚成几根横条）。所以构图里不会出现小角聚集。
   - **位置先均铺再整体乱序加大抖动**，且**允许贴边溢出**：均铺区间从 8~86 放宽到 -6~98、
     抖动从 ±8 放到 ±10，再按各自的厚度钳一次（至少留 `RIBBON_MIN_VISIBLE_VH` 在屏内，
     下限 `−(厚度 − 最小可见量)`——厚的那条可以多溢出一点，各条贴边程度才一致）。
     贴到上下屏沿的那几条会被屏裁掉一段，拼贴才铺得满；全都留在屏内的话四角是空的，
     读出来是几条悬浮的带子。

   要求 units ≥1（单段也只是一条丝带，仍属斜切丝带）。

   **运动分成两条互不牵动的线**：

   - **丝带自身只上下匀速漂移**：一个 plan 内沿固定方向、固定速度滑动
     （`driftVelPxPerSec` 绝对 px/秒，方向按种子定上/下、速度按条 ±20% 抖动，二者都不随时间变），
     不再做正弦往复，也不再「单向漂到被钳住」——正弦往复会让方向来回翻、速度从 0 到峰值变化，
     正是要去掉的「变速 / 变向」；`driftVelPxPerSec` 与歌词、逐字歌词、行时长都无关，只被
     `ribbonDrift` 旋钮整体缩放，极长行上 `速度 × 行时长` 顶到 `driftClampPx` 才停。
   - **文字在丝带上线性滚动，不回绕**：`位移 = pxPerSec × (当前时间 − 本行起始)`。
     `pxPerSec = textPxPerSec × 屏宽`，是一个**恒定**速度——**与歌词、逐字歌词、行时长
     都无关**（不引入 seed 抖动，只随屏幕宽度缩放），每条丝带都一样。竖向漂移仍有各自的
     相位/抖动，所以整叠不会读成一块刚性板。位移只是时间的函数，与份数、周期、帧间隔
     全都无关，所以 seek 稳定、重建一致，也没有接缝可跳。

     滚动**曾经是周期的**（铺 N 份，位移每滚过一份就回绕一次），而回绕要无缝就必须
     让位移**精确等于一份的周期**——周期是量出来的：重铺补份、窗口缩放、字体到位、
     甚至首帧那一刻布局还没稳定，它都会变，位移于是整条改一个比例，而那个差值不是
     周期的整数倍，肉眼就是「匀速滚动中忽然跳一下」（实测一次缩放重铺跳 15px）。

     改成线性之后**周期只用来算「铺几份」**，量差多少都不影响位移，于是永远不会跳。
     代价是内容必须一次铺够「盒长 + 这一行从头走到尾要走的距离」（`travelSlackSec`
     再留 2 秒富余），滚出去的那一段不会回来；走行上限由内容余量封顶
      （`maxTravelPx`），所以末端也永远不会走进盒子。

     **位移预算 = 行窗口 + `travelTailSec`（1s）**，不是只算到行窗口末尾。行窗口说的是
     「这一行唱到什么时候」，丝带在那之后并没有立刻下屏：有空档时它是 `hold` 全亮挂着
     （最多 0.6s），紧邻时还要交叉淡出 0.14~0.28s。预算只算到窗口末尾的话，这一整段屏上
     就是一条**停住的**丝带——「丝带卡了几帧、然后下一个场景刷出来」说的就是它。
     内容本来就按 `travelSlackSec`（2s）铺，所以这一截走得动；真正的上限仍是内容余量
     （`usable − boxLength`），末端依旧不会走进盒子。

   - **入场滑入已移除**：为保证「一个 plan 内方向/速度始终不变」，丝带不再做任何进场滑入，
     建好即在原位开始匀速漂移；也就不会再有「初始化时末端没超出屏幕」或「忽然移动一大段」
     这类由入场引起的现象。

   **厚度是独立的 vh 值，字号是它的固定比例**（`fontVh = thicknessVh × RIBBON_FONT_RATIO`）。
   最早厚度是文字的 `padding`（0.18em 上下），字号一大整条就跟着变粗——「宽度有时太宽了
   （文字也太大）」就是这么来的；改成两者各自独立抽之后，又撞出「字号比厚度还大」的组合——
   字直接顶到胶带的两条边，「文字到丝带边缘的距离」随厚度忽大忽小。现在是固定比例：
   字到上下边各留 `(1 − ratio)/2 ≈ 17%` 的厚度，每条都一样，粗细变了也不贴边。
   厚度区间本身也收窄过一次（2.6~5.4 → 3.4~4.6，各乘 `RIBBON_VH_SCALE`）：原先最粗那条是
   最细那条的两倍多，一叠里粗细差这么大读出来是「几条不同的东西」而不是同一卷胶带。

   **一条丝带是一整句，不分词**：文本取当前行的原文 / 译文（`ribbonTextsOf`），有译文时
   交替上带——**原文与译文不在同一条丝带**（一条带上中英混排是两句话绞在一起）。
   以前取的是切分层的 `units`，于是丝带上会出现半句话。

   **文字必须铺满并越过屏幕边缘**（`fillRibbonText`）。目标长度不是屏宽：丝带是**旋转**的，
   它要盖住的是屏幕矩形在自己轴向上的投影——`ribbonCoverageWidth` =
   宽 × |cos θ| + 2 × max(盒心 y, 屏高 − 盒心 y) × |sin θ|。
   **盒心不是盒子上沿**：`top` 给的是上沿，旋转中心还要往下挪半个厚度（`thicknessVh` 是 vh、
   `top` 是屏高的百分比，两把尺子不同，只能实测 `offsetHeight`），漏掉这半个厚度会让贴边
   那几条短一截。按屏宽算会在大角度、或贴上下边沿的丝带上漏出末端。
   盒长还要再放长一截才够（`ribbonBoxLength`）：覆盖长度 × (1 + `coverageMarginRatio`)
   + 2 × 最坏竖向位移 × |sin θ|——漂移是**屏幕竖向**平移（入场滑入已移除），而盒子绕自己的中心转，
   竖着挪 d 会让屏幕的轴向区间相对盒心偏 d × |sin θ|；只按静止时「刚好盖住」下料，
   位移到极值时那一端就缩进屏幕里。
   份数按「(盒长 + 整行行程) × 安全系数 ÷ 一份的实测宽度」算，再**多铺一份**：滚动是线性的，
   滚出去的那一段不会回来，只铺到「刚好盖住」的话行尾就把末端走出来了。
   盒子的左右溢出也按「(份数 − 1) 份有多长」收，几何只给目标、内容说了算。
   一份的宽度是**量出来的**（`scrollWidth`，量两份解出间隔，所以周期 = 字宽 + 间隔），
   不是按字数估——字数估不准（中英混排、字距、字体回退都会让实际宽度偏离）。
   只量一次（量得到宽度的第一帧；建层时节点还没进 DOM，`clientWidth` 是 0），
   逐帧量会触发同步布局、把整屏拖成掉帧；`ResizeObserver` 报尺寸变化时翻标记重铺，
   字体就绪（`document.fonts.ready`）也重铺一次——字体晚到会让量出来的一份宽度过期
   （现在只影响铺几份，不影响位移）。

   **「基线斜切」不是整字旋转**：丝带来的是「字保持正交、只是落点的基线歪了」，
   整字 `rotate` 会把字本身转歪（像挂歪的牌匾）。两者的差别处在「字形有没有被扭歪」——
   同一个角度下，前者只是每个字的落点沿一条歪线排开，后者连笔画都斜了。

   **质感是丝带自身的，不是层间的**：以前「靠前的层亮、后边的暗」，读出来是 z 轴排序而不是材质。
   现在每条丝带沿自身轴向都有一条稍亮、一条稍暗的段（自身 `linear-gradient`，参数
   `shadeAngle/shadeStart/shadeSpan/shadeStrength`，按种子抽所以 seek 稳定），
   **强度按主题缩放**（暗色主题加强亮的一段、压低暗的一段：暗底上再压黑只会把带子抹掉）。
   渐变垫在文字**下面**——它是胶带自身的材质，压在字上会把字蒙一层。

   **配色与层次跟着主题的亮 / 暗走**（`ribbonSkin`）：带身取 `accent`、字取主题背景色反白，
   两侧都是主题色，所以换主题不用改配色本身；换的是**层次的表达方式**——
   亮色主题屏面是浅的，丝带读作压在屏面上的实物，层次靠**投影**；暗色主题屏面本身就是深的，
   黑投影在深底上几乎看不见，改走 accent 的**外发光**（`color-mix` 让浏览器把主题色透明化——
   主题色格式任意，模组侧算不出可靠的 alpha），才读得出是贴在暗底上的一条亮胶带。
   叠放次序按 `topPct` 降序 append（后来居上）：位置靠下的在上，于是落在它下面那条上，
   像一叠贴上去的胶带。

40 行样本实测三种样式全部出现、相邻行零重复。

**参考图里的舞台效果**（2026MIXUP 那帧）是这版的目标形态：屏面上下各一条跑马灯带、
中间一组巨大的字。带子那一档是靠**边线那道灯**读出来的（带身不填色），
所以 `marqueeFill` 默认「不填色」、`marqueeEdge` 默认「辉光」。

已知取舍：丝带组的反白字直接用 `theme.backgroundColor`，
主题背景本身是浅色时会偏弱；条带实底无法半透明（主题色是任意格式的 CSS 字符串，做不了可靠的
alpha 化），所以叠压关系靠投影而不是透明度。这两点要等主题色统一成可解析色值之后才能改。
大字报的字宽是**按字种估的**（当量宽度），没有量真实字体——遇到特别宽/特别窄的字体时会偏保守
（字略小），但不会出屏。屏面上屏的文字色走 `color-mix` 往白里提，宿主若不支持容器查询 / `color-mix`
（本仓 Electron 43 支持），那条声明会被丢掉并回落到继承色——设置面板本来就依赖 `color-mix`，
所以这不是巨幕新引入的前提。

**屏沿的文字会经过宿主左上角那颗返回按钮。** 那颗按钮是宿主的**悬停显示**元素
（`VisualizerShell.tsx`：指针进入左上 120px 热区才淡入，`z-30` 在模组之上，模组盖不住它，
也不会挡它的鼠标事件），横带现在通铺整条边，带上的滚动字会从它下面穿过——截图里「返回按钮不显示」
绝大多数是**指针不在热区**，把指针移到左上角即可验证。要更清爽只能让横带在左上角让位，
代价是四角重新出现缺口。

## 选项

设置面板由**模组自带**（`settingsPanel.mjs`），挂在**动画模式选择器那张卡片的下面**——也就是
宿主渲染其它歌词动画细节设置面板（`renderSettingsPanel`）的同一个位置，所以巨幕这块和
Luminous / Sonnet 那些设置卡片是同一张脸。只在当前模式是巨幕时显示。

面板是手动插进宿主 DOM 的，宿主不会替我们收走它，所以「什么时候该消失」由模组自己判：
当前模式不是巨幕 → 隐藏（`display:none`）；宿主切到别的分区（通用 / 背景）→ 锚点整块消失，
面板直接从 DOM 摘下来，回到歌词动画这一屏时自动插回原位。判不出来（锚点与选择器都不在、
或锚点的 mode 属性是空串）一律当「不该显示」——反过来的话，面板会留在无关的分区里不消失。
补挂是 400ms 一轮的轮询（宿主重绘没有事件可听），**页面不可见时整个定时器停掉**——
那时宿主既不会重绘、也看不到补挂结果，回前台立刻补一轮。

mod.json 里**不**声明 `visualizers[].settings`：那是宿主会照着渲染一份表单的声明式 schema，
声明了就会和自带面板并排出现两组同样的旋钮，而宿主那份写的 store 巨幕不读（表现为
「上面那组拖了没反应」）。

值写在 `cineramaSettings.mjs` 的共享单例（面板写、渲染层每帧读同一份，所以拖动即时生效），
落盘用模组自己的 localStorage（`folia_mod_cinerama_settings_v1`）并**防抖 250ms**
（滑杆的 input 每移动一格都同步写盘会抖一整条拖动；`pagehide` / `visibilitychange` 时补写最后一拍），经
`hostPanel.resolveCineramaKnobs(props)` 到达渲染层：自带面板的值 → `props.getModulation()`
（实时调制，拖滑块即时生效，盖在持久化值上）。两者都缺席（导出窗口、旧宿主）时全部回落缺省。
宿主那条 `props.getSettings()` 通道刻意不读：巨幕不声明 schema，那条通道里只剩旧版本的值，
读进来会让「面板显示的数」和「画面用的数」对不上。

### 宿主锚点

宿主在动画模式选择器那张卡片里渲染一个空节点，这是它对模组的**唯一 DOM 契约**：

```html
<div data-mod-visualizer-settings-slot="<当前 mode id>"></div>
```

（`src/components/visualizer/ModVisualizerSettingsSlot.tsx`，随 `visualizerMode` 更新属性值。）

模组拿它做两件事：用属性值比对 `mod:cinerama:cinerama-screen` 判定「当前模式是巨幕」
（与语言、皮肤、按钮文案都无关），以及从它往上 `closest('.rounded-[24px]')` 找到那张设置卡片，
把面板插到卡片的**下一个兄弟位**——和内置模式的设置卡片平级。

锚点缺席（旧宿主）**没有第二条路**：不猜位置、不摘节点，直接「面板不出现」（不报错、不影响播放）。
以前这里还有一套按 `data-preset-group-label` 文案定位的回退，而宿主侧从来没渲染过这个属性
（`PresetGroup` 只输出 className/style），于是那条路恒为 null——走进去既挂不上、又每 400ms
把面板摘一次。定位不到卡片时退回把面板直接放进锚点，锚点也没有就不挂。

### 面板单例

巨幕的 `mount` 会在多处各跑一次（播放页、设置面板里的预览），而设置卡片只有一张，
所以 `settingsPanel.mjs` 里的面板是**单例**：后来者共用第一个实例的节点，引用计数归零才拆。

面板是纯 DOM（无 React），样式全部由宿主写在根元素上的主题变量派生
（`--bg-color` / `--text-primary` / `--text-secondary`，见
`src/components/app/presentation/buildAppStyle.ts`），并用 `color-mix()` 混出卡片底色、描边和
滑块——主题色是任意格式的 CSS 字符串，模组侧做不出可靠的 alpha 化，交给浏览器算最稳。
因此亮色／暗色主题自动跟手，宿主换主题时面板跟着变，变量缺席时有中性灰兜底。
值只写模组自己的 key，**不碰宿主的任何 store**。

面板按**用户要调什么**（而不是按代码里的轴）分成五组，每组是一块**小节**：标题走强调色
（`--text-accent`，与内置模式的莫奈面板同一套分层），组间用一条细分隔线隔开——一屏二十多个
旋钮不分组就分不清哪几个是一伙的。多选一都是**平铺按钮组**——下拉在宿主卡片里又窄又高，
和上下那些滑块不是一个节奏。

每条备注都是**纯文本、一行左右**：它由 `textContent` 直接写进 DOM，Markdown 的 `**加粗**`
会原样显示成两个星号；一屏二十多个旋钮，备注三行以上就把面板读成了文档。长度上限与
「不许带标记」两条由 `test/unit/mod-system/cineramaTextStyle.test.ts` 的
`writes knob hints as plain one-liners` 锁住（中文 ≤64 字、英文 ≤240 字符）。备注只写用户能
看到的**后果**（「拖大就可能出屏」「哪一档是兜底」），不写实现。

控件一律**照抄宿主**（判断依据：并排看不出哪个是模组插的）：

| 控件 | 宿主原型 | 规格 |
| --- | --- | --- |
| 多选一 pill | `VisualizerPresetGroup` / `getAccentOptionStyle` | `px-3 py-2 rounded-full text-sm border`；选中 = `--text-accent` 描边 + `inset 0 0 0 1px` 内阴影 + accent 14% 淡底；未选中 = secondary 18% 描边 + 主题背景 28% 底 |
| 「默认」按钮 | `ResetSectionButton` | 卡片**头部右侧**（与标题同一行、`justify-between`），pill + 12px 回环图标 + 文案「默认」 |
| 滑块 | `rangeInputClass` | 6px 圆角轨迹、14px 圆 thumb |

宿主控件是 React 组件，**复用不了**（拿不到 onClick，它重置的也是内置模式自己的 tuning store），
所以是复刻而不是调用。

面板的旋钮按**用户要调什么**分成五组（顺序也照「从整体到局部」：先决定这一幕由哪几种排版
轮着来，再决定字怎么处理、长什么样，最后才是两条叠加上去的东西），每组一块小节：

| 组 | 管什么 |
| --- | --- |
| **内容与概率** | 排版本体的三个权重 + 排版落点的两组权重（「这一幕轮换出什么」） |
| **歌词处理** | 并词强度 / 逐段落位节奏 / 块级运动强度 / 填色方向 / 填色概率 |
| **文字样式** | 字号 / 字距 / 行距 / 斜体比例（大字报与小字报共用一份；斜切丝带与跑马灯带另有自己的尺度） |
| **跑马灯带** | 带型 / 带速 / 带高 / 带内字高 / 歌名概率 / 填色与色轴 / 边线与色轴 / 范围 / 边线辉光 / 边线流动 / 文字辉光 |
| **斜切丝带** | 条数 / 倾角 / 上下漂移 |

**「自动」只出现在跑马灯带的带型上**（关 / 自动 / 双带 / 四边）——「这一句叠不叠带、叠双带还是
四边」本来就该按句随机。**排版本体没有「自动」**：它是三个概率权重，每句按三者之比抽一个，
「自动」和几个显式档位说的是同一件事，而权重还能顺带表达「某档多一点」（见 playbook 第 1 节第 6 条）。
排版**落点**同理由权重表达——居中那一档是兜底，不进旋钮；上下三分之一 / 左右两栏归一组、
宽银幕字幕条单独一组，拖到 0 就是整首不再出现那一组。

**内容与概率**

| 设置 | 范围 | 作用 | 生效时机 |
| --- | --- | --- | --- |
| `heroWeight` | 0~1（默认 **0.4**） | 大字报的**概率权重**：整行按词切块逐块闪现 | 即时（重编 program + 重建） |
| `smallWeight` | 0~1（默认 **0.2**） | 小字报（兜底样式，任何行都排得下）的权重 | 即时（重编 program + 重建） |
| `ribbonWeight` | 0~1（默认 **0.4**） | 斜切丝带的权重：整句上带、斜切拼贴 | 即时（重编 program + 重建） |
| `layoutEarlyWeight` | 0~1（默认 **1**） | **偏置落点**（上/下三分之一、左右两栏）聚在一起的权重。0 = 整首不再出现这几档 | 即时（重编 program） |
| `layoutLetterboxWeight` | 0~1（默认 **0.5**） | **宽银幕字幕条**（字号更小、字距更宽、压屏体下缘）的权重 | 即时（重编 program） |

两条编译期轴（样式、排版落点）各有一组权重，共用 `cineramaStyleWeightSignature` 这一个签名：
权重一变，每一行的结论都可能换，所以光重建当前层不够——渲染层按这个签名判定要不要
**连带重编 program**（见「权重与签名」）。

**歌词处理**

| 设置 | 范围 | 作用 | 生效时机 |
| --- | --- | --- | --- |
| `heroChunkChance` | 0~1（默认 **0.55**） | 大字报并词概率：按词分词后，每收一个词按此概率再并下一个（0＝每词一闪，1＝装得下就并到底） | 即时（重建） |
| `unitStagger` | 0.4~2（默认 **0.6**） | 一段落位要花多久（`0.3 × unitStagger`，再被该段自己时长的一半钳住）。**不改出词落点**，落点由词时序决定；只改落下去的快慢 | 下一行入场 |
| `heroMotion` | 0~1.5（默认 **1**） | 块级**持续运动**的幅度倍率（推近/拉远/横移/摊开一起缩）。0 = 块落定后完全不动；1 = 设计默认 | 即时（重建） |
| `heroFillAxis` | 自动（默认）/ 水平 / 竖直 | 「跟着唱填满」那一档的推进方向。自动 = 按块抽横或竖、**相邻两块不重复**；钉死之后整首只走一个方向 | 即时（重建） |
| `fillChance` | 0~1（默认 **1**） | 填色的概率倍率（1 = 设计默认，本来就只在长块上偶尔出现）。0 = 整首不再填色 | 即时（重建） |

**文字样式**（大字报与小字报共用一份；斜切丝带与跑马灯带上的字各有自己的尺度，不受这四项影响）

| 设置 | 范围 | 作用 | 生效时机 |
| --- | --- | --- | --- |
| `fontScale` | 0.8~1.3（默认 **1**） | 在「一次出的词都不出屏」算出来的**安全字号**上再乘一次。**>1 就可能出屏**（大字报被屏沿裁掉、小字报整块顶上屏沿），这是刻意的：安全字号是保底，不是上限 | 即时（重建） |
| `letterSpacing` | 0.6~1.6（默认 **1**） | 字距倍率（乘在排版轴给的 `tracking` 上）。整块跟着变宽，所以拖大之后安全字号那一侧可能也要跟着收一点 | 即时（重建） |
| `lineHeight` | 0.85~1.25（默认 **1**） | 行距倍率（乘在排版轴给的 `lineHeight` 上）。调小＝折出来的两三行贴得更近 | 即时（重建） |
| `italicChance` | 0~1（默认 **1**） | 大字报里用斜体的块的比例（乘在本体常量 0.35 上）。0 = 一块都不斜。CJK 没有真正的斜体字面，浏览器会做合成倾斜——中文歌词开高了会读成渲染出错 | 即时（重建） |

字号这一项**只乘一次**：解算层算出来的 `heroFontVh` / `fontVh` 是安全区的结论（也用于
「能并多大块」与让开带子的算术），渲染层只把它再乘一次就写进 CSS。两处各乘一遍就会出现
「面板显示的倍率」和「画面实际用的字号」对不上。
`heroScale` / `smallScale` 这两个旧旋钮已经**从面板撤下**（解析层保留它们只是为了兼容旧安装的
存量 localStorage），现在用户侧只有「文字样式 · 字号」这一条乘法链，落在渲染层写 CSS 的那一处。

写出去的那条 CSS **只兜像素下限**（`minFontPx`：极小窗口别把字压到看不清），**不写上界**——
解算层的 `maxFontVh` 已经是上界，而 vh 跟着屏高缩放，高屏上它本来就是等比例的大字。这里曾经
有一条 `maxFontPx`（236px，即 26vh 在 907px 高屏上的像素值），结果是屏体一旦高过 907px，
CSS 那条上界就抢在 vh 之前接管：1440 高的屏上倍率的顶端约四分之一行程失去反应，2160 高
（4K 全屏）时连默认值都压在上界，整条滑块完全失效。**vh 旁边不要挂绝对像素上界**，这是它留下的教训。

**跑马灯带**（叠加元素：可叠在大字报／小字报上，斜切丝带不与它组合）

| 设置 | 范围 | 作用 | 生效时机 |
| --- | --- | --- | --- |
| `marquee` | 关 / 自动 / 双带 / 四边 | 叠加哪一带型（自动＝按句抽双带或四边） | 即时（重建） |
| `marqueeFill` | 不填色 / 淡色底 | 带子那块区域**着不着色**（默认「不填色」＝实录那一档：带子就是屏体，靠边线那道灯读出来） | 即时（重建） |
| `marqueeFillColor` | 强调色 / 辅助色 | 淡色底取哪个**色轴**（默认「强调色」＝与带上的字同一个光源） | 即时（重建） |
| `marqueeEdge` | 不画边 / 实线 / 辉光 | 区域**边沿**怎么画（默认「辉光」＝与字同一个光源的灯槽） | 即时（重建） |
| `marqueeEdgeColor` | 跟随 / 强调色 / 辅助色 | 边线取哪个**色轴**（默认「跟随」＝实线辅助色、辉光强调色，即旧观感） | 即时（重建） |
| `marqueeEdgeSides` | 内侧 / 双侧 | 边线画在**哪几条边**上（默认「内侧」＝只画朝屏幕中心的那条／那四条） | 即时（重建） |
| `marqueeGlow` | 0~1.5（默认 **0.3**） | **边线**那道灯的辉光强度（面板上叫「边线辉光」）：缩放「辉光」那档的**扩散半径**（浓度走得平一些），**双向**，带内带外各一份；0＝整档淡出。**不动带上的字** | 即时（重建） |
| `marqueeTextGlow` | 0~2（默认 **0.2**） | **带上文字自己**那圈同色光的半径与浓度（面板上叫「文字辉光」）（1＝设计基准的弱影，2＝字自己在发光）。**不动**暗投影，也不动边线那道灯 | 即时（重建） |
| `marqueeSpeed` | 0.2~3（默认 **1**） | 带上文字滚动的速度。**与歌词长短、文本内容无关**（见下面的「带速与文本长度无关」） | 即时（每帧读） |
| `marqueeEdgeDrift` | 0~3（默认 **0**） | 边线那道灯沿带子**流动**的速度（0＝灯不动，就是一条固定的边）。与带速是两件事：字在走、灯也在走。实现见下面的「流动的边线」 | 即时（每帧读） |

**带速与文本长度无关**（`marqueeSpeed`）。

根因在**位移的单位**上：位移写的是「一份」的百分比（双带 `translateX(-100/份数 %)`、
四边 `startOffset`），按「**每秒走几份**」算就等于把速度钉在内容上——而一份的长度完全随文本走。
实测（chromium，1280×720 屏体，同一块屏）：4 字的一份 266px → 45 px/s，48 字符英文的一份
1452px → 301 px/s，差到 **6.7 倍**，而且短的那一头恰好**更慢**：短句慢得像爬、长句快到读不清。

现在速度写成**「每秒走几屏」**（`screensPerSec`，由 seed 抽——它是屏级的艺术决定，
与这一行抽到哪句话无关），周期 =`一份长度 ÷ (屏宽 × 每秒几屏)`。
**文本长度只出现在分子**，正好把那一头的内容依赖抵掉：

| 文本 | 一份的长度 | 归一后实测速度 |
| --- | --- | --- |
| 「夜色」（2 字） | 160px | 302.4 px/s |
| 「夜色报纸」（4 字） | 266px | 302.4 px/s |
| 10 字 / 22 字 / 英文 48 字符 | 586 / 1224 / 1452px | 302.4 px/s |

（`screensPerSec` 同一个 seed 下是 0.2362，302.4 = 0.2362 × 1280——**屏宽 × 几屏每秒**，
与一份的长度无关。上表是逐帧量 `getComputedStyle().transform` 的位移算出来的。）

两档带型共用这一条口径：四边环的「一份」是环上那一段的弧长（`state.unitPx`），
屏宽按根字号（`1vh`）× 宽高比折算——环没有「盒子宽」这一说，`boxPx` 给的是
**绕一圈的周长**（实测 3595px），不能当屏宽用。

三条实现上的注意：

- **周期要的那几个环境量一次量齐**（`readBandStageMetrics`：根字号 / 视口宽高 / 带盒宽），
  随每帧的旋钮快照下发（与宽高比同一条路）。它们只在窗口缩放与字体到位时才变，
  而 update 每帧都要算周期——各自现读的话那条读还夹在样式写入之间，
  每帧都是一次同步布局。
- **量不到就冻结相位**（不写 `transform` / `startOffset`）：节点还没进 DOM、导出窗口量不出尺寸
  时，停住比拿缺省值往前冲安全。解算层给的 `marquee.period` 是常量周期那一份，
  与内容无关，排版落定那一帧接得上、不跳。
- **`marqueeSpeed` 是「每秒走几屏」的倍率**（乘在 `screensPerSec` 上），所以拖带速缩放的是
  屏上速度，仍然与文本长度无关。

**流动的边线**（`marqueeEdgeDrift`，缺省 **0**）——辉光那档的落点沿带子走，读作一道「在跑的灯」。
缺省压到 0 是因为带上的字与边线本来就挤在同一个纵向区间里：让它沿带子走就会穿过字身、
读成第二条线。这一轴**没有被删**，往右拖照样有（振幅 = `edgeDriftSpan` × 这一轴）；
驱动方式是给内沿那个节点写一段竖直位移（±`edgeDriftSpan`% 带高，两端配一层淡出，
不至于像一条被瞬移的边）。

灯在跑的时候，推的是**内沿那一个节点**（`haloNode`）——它本来就是内沿的唯一一份，
所以「一份钉在边上、一份在旁边滑」这件事在结构上不可能发生。外沿是屏幕自己的框，
钉在屏沿上不动，永远不跟着灯跑。

**偏移恒为 0**。同心阴影不可能落错边，所以「偏移=半径」那条约束不再需要——它只是
定向阴影时代用来把偏差压到最小的补丁。三层各自的**半径**仍然要小于一个带厚（见上一节）。

**`edgeDriftSpan` 默认 0**（原先是 6%）：带上的字与边线本来就挤在同一个纵向区间里，
让这道灯沿带子走就会穿过字身、读成第二条线；`edgeDriftFloor` 从 0.35 提到 0.8，
因为走到端点只剩三成亮度时，那道灯会与边上那条拉开距离、看起来像**另一条更暗的线**浮出来。
振幅为 0 时连不透明度也不动——否则「一条稳定的边」会读成「一条时亮时暗的边」。

**带上的文字辉光**（`marqueeTextGlow`，缺省 **0.2**）——这里同时踩过一个真实的坑：
带上文字的同色辉光**从来没有生效过**。

被削弱的理由本身是对的（实录里那条带子的亮来自**边线那道灯**，字是干净的），
所以这一档只留一圈很淡的同色光。但它必须写成**三个长度**：
`text-shadow` 只收 `offset-x offset-y blur`，**没有 spread**（第四位是 `box-shadow` 的语法），
多写一个长度会让**整条 `text-shadow` 声明被丢弃**——被丢掉的除了那层暗投影，还有
**紧随其后的同色光**，带层宿主的 `text-shadow` 在真实浏览器里会一直是 `none`。
所以 `dropBlur` 落在 blur 位上：
竖向影响范围仍然「约等于下落量 + 一小段模糊」，而下落量本来就按字号取很小的一个比例。

面板这一轴缩放的是**同色光的半径与浓度**（线性乘，不是 `floor + …` 那条曲线：
拖到 0 就该是**不画**，而曲线会让 0 还留着一圈看得见的光）；暗投影**不跟它走**——
暗投影管的是浅色画面上的可读性，不是发光。

| 档位 | 半径 | 浓度 |
| --- | --- | --- |
| 0 | 0 | 0（同色光整档不画） |
| 0.2（缺省） | 基准的 2 成 | 基准的 2 成 |
| 1 | 基准（带内字号 × `shadowBlur`） | 基准（`shadowAlpha` 55%） |
| 2（上限） | 基准的 2 倍 | 顶到满浓度 |

**带上的字影不许越过内沿，而且行盒不许往里缩**。带盒是 `overflow:hidden` 的，而一个字的
`text-shadow` 是**四周**一圈：往上那一半落在带子里的屏面上（正常），**往下那一半会越过内沿、
被盒子切掉**。切出来的边界不是直的——它逐字复刻下面那个字的轮廓（汉字下缘是横竖撇捺），
读出来就是内沿上浮出一道跟着字起伏的波浪。

**「把行盒下缘往上缩」修不掉它**：**行盒的 overflow 从来不含 descender**，汉字与拉丁字母
的下缘笔画（竖钩、捺、`g/j/p/q` 的尾巴）本来就在行盒外面，把盒子缩一圈等于拿刀去切字形——
切出来的边界照样逐字复刻，还是那道波浪。

所以改成：**字影自己收，行盒不缩**。

- 暗投影只收**三个长度**（`0 <下落>cqh <模糊>px`，见上面那一节：「四个长度会被整条丢掉」），
  影响范围 = 下落量 + 一小段模糊；**下落量按带内字号取比例**
  （`TUNING.marquee.text.baselineDropRatio` = 0.03，缺省字号 6.6cqh → 约 1.4px），
  不能写死 px——字号本身就是带高的一个比例，写死 px 意味着某一档带高下它会忽然越出去；
- 同色光**不下落**（`0 0 <半径>`）：它四周均摊，一半落在带内屏面、一半压在内沿，
  把字与边线接起来——但它**不下落**，所以不在任何一条边上留边界。半径与浓度由
  `marqueeTextGlow` 缩放（见上面那一节）；
- **行盒按量出来的字高自己居中**（`inner.scrollHeight`，量到的第一帧算一次）：行盒的 overflow
  判定用行盒，而字形会画到行盒外面，所以 `clientHeight` 兜不住下缘、`scrollHeight` 才是
  「字形到底铺了多高」在 DOM 上能拿到的那一份。

**居中这一句有两条支路，两条都得有**：

- 行盒比带子**矮**（常态：带内字号压在带高的六成以内）→ `margin-top` = `(带高 − 字高) / 2`
  的**正值**，把字推到带子的中线上。四边环的字心天然落在环线上（`dominant-baseline: central`），
  这一支就是双带的等价物；
- 行盒比带子**高**（带厚拖到端点、或宿主字体把行高撑开）→ 同一条式子给出**负值**，
  也就是上下各伸出去溢出量的一半，左右补同样的量（免得横向溢出跟位移叠在一起让两端露白）。
  伸出去的部分落在带子的**外面**——带盒把它裁掉也看不见，能看见的字影于是始终在行盒以**内**。

**只写后者字就会全挤在内沿那一侧**：`Math.max(0, …)` 把常态那一支归零，行盒于是贴着
带盒的 `top:0`，外侧空出一大截。同一条式子的两种取值都要留，所以也别写成两支 if——
写成 `(带高 − 字高) / 2` 一个式子，正负自然出来。

两条合起来，屏上只剩**一条边线自己的灯**——这也正是设计意图里那条
「实录里带子的亮来自边上那道灯，字本身是干净的」。

**斜切丝带**

| 设置 | 范围 | 作用 | 生效时机 |
| --- | --- | --- | --- |
| `ribbonCount` | 3~9（默认 **6**） | 丝带条数 | 即时（重建） |
| `ribbonAngle` | 0.4~1.4（默认 **1**） | 丝带角度幅度 | 即时（重建） |
| `ribbonDrift` | 0~3（默认 **1**） | 丝带**上下漂移**的速度（0＝不动，速度本身是恒定的，钳位之前不加减速）。文字在带上匀速滚动，不受这项影响 | 即时（每帧读） |

结构旋钮（带型、填色与边线、边线辉光与文字辉光、文字样式四项、歌词处理里的斜体/填色/运动、带高、
带内字高、歌名概率、并词、条数、角度、宽高比）变化时由 `cineramaStructureSignature`
触发当前层立即重建，不用等下一行；连续旋钮（各种速度、漂移、落位节奏）每帧现读；
**两组权重**（样式、排版落点）不重建当前层，而是走 `cineramaStyleWeightSignature` 重编 program。
`cineramaTreatment.mjs` 顶部的 `CINERAMA_TUNING` 仍是代码级常量（不进面板）。

## 舞台屏体

`cineramaStage.mjs` 只负责「硬件」：**铺满整个舞台的屏体**（`inset:0`）+ 扫描线、一层很浅的暗角，
以及歌词所在的 text host。chrome 叠层一律黑白 alpha——主题色是任意格式的 CSS 字符串，
做不了可靠的透明化（唯一例外见下面的 `screenText`）。

以前屏体是居中一块 92%×56% 的圆角屏：屏外露出一圈底色，屏沿还有外投影 + 2px 内描边 + 强暗角——
在浅色主题下那一圈就读成**黑框**，而且屏体本身没把舞台填满（跑马灯带也因此永远够不到舞台边缘）。
现在屏面不再有边框、圆角与投影：它是一整面墙，不是挂在墙上的一块板。改这个尺寸会牵动所有
「屏内的 vh 量」（大字报上限、小字报与丝带的 vh 区间），它们已经按屏高比值整体放大过一次。

屏面还必须**几乎不透明**（alpha 0.94~0.98）：先前是半透明黑，压在浅色的宿主背景上会整块变成
一片浅灰——既不是「墙」也不是宿主的背景（「画面里整体填充了错误的浅灰色」就是这么来的）。
斜向眩光也一起去掉了：那是给一块居中面板做的受光，铺满之后变成横跨整个画面的一道浅色。

屏面上的**文字**取 `palette.accent`（主题强调色）：小字报 / 大字报 / 跑马灯带上的字共用这一份
（`cineramaRender.skinOf` / `bandSkinOf` 的那条 `color`）。屏上要的是主题里那个**用来点睛**的颜色，
而不是主题的正文文字色——后者是一支近白的中性墨，跟丝带的反白字、跟主题其它界面文字都分不开，
「同一块屏上的字」这个身份就没了。

**可读性按「这一块字有多大」分两档**（`skinOf` = 正文 / `bandSkinOf` = 带上的字）：

- **正文**（小字报 / 大字报）：整屏就一句话，一个字能撑满一大块屏，所以挂得动
  `0 2px 14px rgba(0,0,0,.55)` + `0 0 30px <accent>` 这一厚一薄两层影；
- **带上的字**：一圈循环密排的小字，字距本来就紧，同一份影挂上去就是「字被自己的光糊住」
  ——实录里带子的亮来自**边上那道灯**，字本身是干净的。所以只留
  `0 2px 6px rgba(0,0,0,.3)` + 一圈半径为带内字号 0.22 的淡同色光（`TUNING.marquee.text`）。

`palette.screenText`（主题文字色用 `color-mix(in srgb, <主题文字色> 14%, #fff)` 往白里提过的那个）
现在只剩一个用处：解算失败时的**兜底正文层**（见 `visualizer.mjs`）。跑马灯带的区域底改成强调色的
极淡底、边线走 `accent`（辉光档）或 `secondary`（实线档），都不再取中性色。
斜切丝带两边都不走这里——它是实底胶带，带身取 `accent`、字取主题背景色反白（见 `ribbonSkin`）。

**透明表面不画屏面**（`props.transparentSurface`）。播放页开了透明背景、OBS 浏览器源、
以及模组的透明导出窗口，宿主给的已经是一块透明表面：屏面是一整块不透明的墙（`inset:0` + 渐变），
画上去整帧就变成实心矩形——「需要透明背景的时候用了不必要的背景色」。这类宿主下
`createCineramaStage` 只建 text host（它自己没有背景），屏面、扫描线、暗角全部跳过，
`applyPalette` 退化成空操作。文字的可读性由它自己的 `text-shadow` 承担。

屏体同时是一个 **size container**（`container-type:size`）：屏内因此有了一套真正的
「屏体百分比」（`1cqh = 屏高的 1%`），跑马灯带的字号靠它才不会比带子还高。
逐帧写样式的只有 textHost 一个节点，且经 last-value 缓存去重：值没变的帧零失效。换行才重建 DOM
（`renderPlan`），竖直 padding 用 `em` 而不是 `%`——百分比 padding 按屏体**宽度**解析，
2.4:1 的墙上会把纵向留白吹起来。

## 宿主接入：背景与底部字幕

这两层由宿主渲染（内置模式也一样），模组侧只负责配合——它们不是巨幕自己的东西，但「看不见」
的两种表现都在这里：

1. **「背景类型」定义的背景**。宿主在外壳里挂 `VisualizerBackgroundRenderer`（`VisualizerShell`
   的 `renderBackground`，缺省就是挂），并把整份配置经 `props.background` 交给贡献层——
   与内置模式读的是同一个对象。巨幕据此**让出屏面填充**（`hasCineramaHostBackground` →
   `createCineramaStage({ hostBackground })`）：扫描线与暗角留着（它们是 alpha 纹理，不挡背景，
   也是「巨幕」自己的画面语汇），只去掉那层不透明的墙。否则那面墙会把用户选的背景整块盖住，
   在设置里怎么切「背景类型」都对巨幕不生效。
   让位是**一条 background 声明**，不重建舞台（`applyScreenFill`）——textHost 上挂着正在放的
   内容层，重建会把它们一起拆掉；`paint` 每帧比对 `props.background`，换背景即时跟上。
   判据只有 `background.transparent` 一条：为真 = 透明表面（播放页透明 / OBS 源 / 导出窗口），
   那时宿主的背景渲染器直接返回 null，屏面本来就整块不建（见「舞台屏体」）。
   **旧宿主没传 `background`** 时按「宿主没有背景」处理，屏面照旧，行为与之前一致。
   代价：墙让位之后，文字与背景的对比由主题配色自己承担（正文与带上的字是 `accent`、带底是它自己的
   极淡底、边线是 `accent` 或 `secondary`，全是主题色），换成一张高对比的图片背景时可读性会下降
   ——这是这一档的已知取舍。
2. **底部字幕（翻译 / 下一句预览）**。宿主在同一个外壳里渲染共享的
   `VisualizerSubtitleOverlay`，字号缩放、透明度、底栏偏移、模糊、内容口径全部走宿主的字幕设置；
   模组这边**什么都不用做**，也不需要自己实现一份。它 `z-20` 盖在巨幕画面之上，所以底部的
   跑马灯带会被它压住——字幕只在有译文/下一句时出现，属于可接受的叠压。

## 渲染端契约与已知坑

- 时间只从 `props.currentTime`（MotionValue）订阅，不进 React state；`staticMode`（模式缩略图）
  走一次性 paint，不订阅。
- `props.transparentSurface` 为真时不建屏面（见「舞台屏体」）。它由宿主的
  `background.transparent` 透传（播放页透明 / OBS 源 / 导出窗口都是真）；旧宿主没这个字段时
  按 `false` 处理，行为与之前一致。
- `props.background` 是宿主已在模组后面渲染的「背景类型」配置（与内置模式同源，见
  「宿主接入：背景与底部字幕」）。为真（非 `transparent`）时屏面填充让位；宿主没传 / 值坏掉时
  维持自己画屏面的原行为。它是**挂载那一刻的快照**，跟着用户设置走的那条通路是
  `props.getBackground()`（见下一条）。
- `props.getTheme()` / `props.getBackground()` / `props.getModulation()` / `props.getSettings()`
  都可能不存在（导出窗口、旧宿主），渲染层必须在缺席时按缺省工作；返回值要**每帧读**，不能缓存
  （见「选项」）。前两个缺席时退回挂载那一刻的快照（`props.theme` / `props.background`）。
- **加载器只给入口 URL 加版本**（`?v=<内容摘要>`），子模块是裸相对路径，会留在浏览器 ES module
  map 里——改了除 `visualizer.mjs` 以外的任何文件后要重载窗口才生效。要彻底解决得让子模块也带
  版本，代价是入口改成 top-level await 的动态 import，现阶段不值得。
- `folia-mod://` 只服务 `.js/.mjs`、只服务已启用且加载成功的模组；透明导出窗口没有 preload，
  模组 visualizer 由主进程随渲染配置注入，所以 `mod:cinerama:cinerama-screen` 在导出里同样可用。
- labelKey 不能带冒号：i18next 默认 `nsSeparator: ':'`，`ui.modVisualizer.mod:<id>:<viz>` 会在
  查词典前被拆掉命名空间，`parseMissingKeyHandler` 拿到残片后 `getVisualizerModeLabel` 的
  fallback 判定失效，设置界面会直接显示内部 mode id。`src/mods/modVisualizers.tsx` 已把 mode
  点号拼接后再拼进 labelKey，改这里时别改回去。

## 排查：看不到设置 / 效果没变

按顺序查，前三条占了绝大多数情况：

1. **面板要选到巨幕才出现，而且要等一次挂载。** 面板是在巨幕的 `mount` 里挂上去的，
   所以顺序是「打开设置面板 → 动画模式选巨幕 → 面板出现」。它插在动画模式那张卡片里
   （锚点 `[data-mod-visualizer-settings-slot]`），往下滚一点就是。
   如果一直不出现：看 DevTools 里那个 `data-cinerama-panel` 节点在不在——没有就是宿主布局变了，
   有但隐藏就是面板判错模式了（只看锚点与宿主给出的当前模式 id，与界面语言无关）。
2. **改了子文件要重载窗口，不是点「重新加载」。** 加载器只给入口 URL 加 `?v=<摘要>`，
   `cineramaRender.mjs` 这类子模块是裸相对路径，会一直留在浏览器 ES module map 里。
   点面板的「重新加载」只会重新 import 入口 + 重跑 Node 侧代码，渲染层仍是旧的那份——
   必须 Ctrl/Cmd+R 或重启应用。
3. **确认跑的是哪一份副本。** 目录扫描顺序见 `electron/modSystem/modSystem.cjs` 的
   `getModsDirectories`：开发版先扫仓库 `mods/`，打包版先扫 `userData/mods`，同 id 只认先扫到的。
   如果 `userData/mods/cinerama` 下留着旧副本，改仓库里的文件完全不会影响它。面板显示的版本号
   和主进程日志（`cinerama <version> loaded ...`）能直接对上：对不上就是跑错副本了。
   两处读的是同一份真相——manifest 的 `version` 是唯一来源，日志由 `index.cjs` 从 `api.manifest` 读出。
4. **内容变了会撤销信任。** 任何文件改动都会让摘要失配，模组保持禁用直到重新确认——
   只点「启用」不够时要看面板是否提示需重新确认。
5. 症状若是「整屏冻住而不是某一句没效果」：那是 paint 抛异常断掉了 MotionValue 订阅。
   `visualizer.mjs` 已对建层和逐帧更新都做了兜底（退化成朴素整行并 `console.warn`），
   开 DevTools 看 `[cinerama]` 前缀的警告即可定位到具体 plan。

## 逐字时序（跟唱，不等分）

出词的时刻**来自 parser 的词时序，不是在行窗口上等分**——等分会把出词摊到整段显示窗口上，
让每一次闪现都比唱到它的时候晚一截，原因在「落点」上：

**行窗口（`window.endTime`）说的是「这一行在屏上待到什么时候」，它含一段没人唱的尾巴。**
作者写的 `line.endTime` 常常落在最后一个词之后，`renderHints.renderEndTime` 还要再加
`linePassHold + exitDuration`（见 `src/utils/lyrics/renderHints.ts` 的 `buildLineRenderEndTime`）。
把出词摊到整段显示窗口上，每个词都会比唱到它的时候晚一截，尾巴越长晚得越多。实测一行
3s、末尾 0.6s 没词时，第二段晚了 **1.05s**；换成词时序后实测逐段误差 **+0.00**。
tempera 的 README 里那句「凡是按歌词节奏走的东西都要用 `lyricEndTime`，否则会拖成好几秒」
说的是同一件事。

两条落点因此分开：

- **歌词窗口** `resolveCineramaRevealWindow`——出词用它。终点取最后一个词的 `endTime`
  （没有词时序时退回作者写的 `line.endTime`），并给一个下限（`REVEAL_FLOOR_RATIO`）
  兜住坏数据。它是**这一段唱词的边界**：大字报最后一块顶到它，没有词时序时的等分兜底也摊在它上面。
- **显示窗口** `window`——这一行在屏上待多久、转场什么时候起，仍然用它。

有词时序时走 `buildCineramaGraphemeTimeline`：它是 `src/utils/lyrics/graphemeTiming.ts`
的 `buildLineGraphemeTimeline` 的**本地镜像**——模组跑在 `folia-mod://` 下 import 不到
`src`，只能照同一套口径再实现一遍（词内字素等分、词间未被覆盖的字素零时长）。
一段的时刻 = 它覆盖的那些字素的 `[min 起点, max 终点]`；对位成立的前提是 parts
**无损**（拼回去等于原文），拼不回去就整体退回等分。

**两种「段」走同一套对位**（`buildCineramaUnits` 的 parts / 大字报的块）：

- **units**（小字报的 span、丝带取文本）——切分层切出来的段，无损。
- **大字报的块**（`resolveCineramaSegmentSpans`）——按词并出来的块，**每块以自己第一个字素的
  时刻入场**。这条以前是「歌词窗口 ÷ 块数」均分：均分只在词距均匀时才对，唱得快、而这一行的
  显示窗口还长着一大截时，后面的块会一路滞后——实测 5 块能差到 **1.60s**（唱到 10.8s 的末块
  排到了 12.4s），正是「歌词时间戳正常、大字报出字明显滞后」。换成按块自己的词之后逐块误差 **+0.00**。
  与 units 的两处差别：块的**尾随空白可能已被裁掉**（`trimEnd`，否则空格占宽度、居中的字会歪），
  对位时跳过；块与块之间**不留空屏**——下一块的起点就是本块的终点（词间的停顿由前一拍驻留顶着），
  最后一块顶到歌词窗口终点。
  **对位本身从不放弃**：字符对不上（分词过期、归一化不同）就按顺序继续，游标停在哪儿就用哪儿的
  时刻——与宿主同一条宽容口径（`graphemeTiming.ts` 的 `findGraphemeSequence` 没命中就是
  `start = cursor`，同样不会把整行摊平）。
  **唯一退回均分的情况是「API 根本没给出可用的词级顺序」**：块的起点没能严格递进（整行的词共用
  同一个时刻、或时刻全被钳到窗口边缘）。那时几块会挤在同一瞬间，而渲染层是按 `[start, end]`
  判可见的——零长窗口等于「这一行只闪出最后一块，其余的字永远不出现」。这时摊开的依据也是
  **宿主自己的口径**：`buildLineGraphemeTimeline` 在 `line.words` 为空时同样是把整行摊平
  （`src/utils/lyrics/graphemeTiming.ts`），而那是个真实输入——纯时间戳的歌词行 parses 出来就是
  `words: []`（`parserCore.ts` 的 `drafts.push({ words: [], ... })`）。

两条从别处搬来的坑，实现里已经处理：

1. **零时长的字素要重新计时**。src 那份把它们钉在**后一个词**的起点，于是逗号会跟着
   它后面那个词一起入场（tempera 的 README 明确记了这条）。这里改钉到**前一个字素的结束**，
   标点于是跟着它前面的内容走。
2. **单调 + 钳位收尾**。词时序是外部数据，可能有脏值（时间戳超出行窗口、整段偏移、
   相邻词时间倒挂）。不论它说什么，出词顺序不许倒退、时刻不许离开行窗口——出了窗口这一段
   要么永远不入场，要么在下一行已经开始之后才出来。
